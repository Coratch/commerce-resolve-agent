# CommerceResolve v0.1 Agent Eval 报告

状态：Passed  
日期：2026-07-17  
场景集：`commerce-resolve-v0.1`

## 评估范围

本报告使用真实 LangGraph 工作流、Fake 意图解释器以及 Fake 订单和物流 Gateway，
确定性验证 v0.1 的业务结果、逐轮工具轨迹、工具参数、安全边界和 SQLite
跨实例恢复。

本报告不评估 DeepSeek 的语义准确率、真实订单系统、线上延迟、Token 成本、RAG、
退款或人工客服。DeepSeek 仅完成一条独立手工冒烟，不进入离线发布指标。

## 复现命令

```bash
conda activate ecom-agent
python -m commerce_resolve eval
```

命令输出完整 JSON 场景轨迹；任一发布门槛失败时返回非零退出码。

## 场景分布

| 类别 | 数量 | 核心断言 |
|---|---:|---|
| 有效订单与物流查询 | 4 | 返回经过 Gateway 验证的订单和物流事实 |
| 缺少订单号与多轮补充 | 3 | 首轮不调用工具，补充后继续原任务 |
| 不存在订单 | 2 | 不查询物流，不返回业务数据 |
| 未授权订单 | 2 | 与不存在订单使用相同公开语义 |
| 业务工具失败 | 2 | 停止后续调用并返回脱敏错误 |
| 不支持写操作 | 2 | 不调用订单或物流工具，不产生写操作 |

其中 `missing-order-cross-process` 在两轮之间关闭 SQLite 连接并重新构建 Graph，
验证相同 `thread_id` 能够恢复等待状态。

## 结论与限制

v0.1 的只读订单查询、会话恢复、身份隔离和安全失败满足已接受的发布门槛。
这只证明固定 Fake 数据下的工作流契约，没有证明真实模型和真实业务 API 的生产质量。
后续版本必须延续固定场景，并为新增 RAG、退款和 Handoff 能力分别增加对应指标。
