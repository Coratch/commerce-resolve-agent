## 评估范围

本报告验证公开对话从浏览器组件内存升级为服务端产品数据后的完整闭环：

- 公开历史恢复、分页、引用和动作卡片投影。
- 会话新建、列表、归档、恢复、删除和身份隔离。
- 消息与决定的稳定客户端标识、Run 幂等和单会话并发门禁。
- 后台 Graph、步骤级 SSE、`Last-Event-ID` 重放和明确终态。
- 退款、L2 升级、L2 补充信息和长期偏好决定的刷新恢复。
- 失败、进程中断、显式重试、旧会话 partial 标记和兼容同步入口。
- 公开消息、Checkpoint、业务事实、政策索引和长期记忆的数据边界。

发布门禁使用 Fake Model、临时业务数据库、临时 Checkpoint、临时 Memory Store 和本地政策
索引，不访问网络、真实 API Key、真实支付或外部业务系统。

## 浏览器人工验收

在本地同源构建中使用管理员账号完成：

1. 在 `/chat/:threadId` 按 Enter 提交“帮我看看 ORD-001 到哪里了”。
2. HTTP 返回 `202 Accepted`，浏览器通过 Run SSE 获得最终公开订单/物流回答。
3. 刷新同一 URL，页面先显示恢复状态，再从服务端重新加载相同用户消息与助手消息。
4. 服务端日志确认消息 POST、SSE、会话列表和历史 API 均成功，浏览器控制台无错误。

该验收只使用本地 Mock 订单和服务端公开投影，不访问真实电商或交易系统。

## 数据与迁移

- Python 包、FastAPI OpenAPI 和前端包版本为 `0.6.0`。

- v0.6 迁移前已有会话标记为 `history_state=partial`，不会从内部 Checkpoint 推测公开历史。

## 结论与限制

v0.6 在本地单实例范围内完成了“接受请求 → 后台 Graph → 持久步骤事件 → SSE 重放 →
公开历史恢复 → Pending Action 继续 → 会话生命周期管理”的最小闭环，并达到全部离线发布
门槛。

结果不能外推为生产客服系统。当前仍使用 SQLite、单 Uvicorn worker 和进程内
`BackgroundTasks`；进程退出时进行中的 Run 只会标记为 `interrupted`，需要用户显式安全
重试。系统不提供 Redis/Worker、多实例广播、Provider Token 流、消息搜索/编辑/分支、
附件、真实支付或真实客服接入。
