# v1.2 双产品表面验收报告

状态：Candidate

版本：`1.2.0`

## 结论

v1.2 T1–T8 已实现并通过当前 macOS 本机产品验收。客户售后中心与 Agent 运营控制台已经形成
独立信息架构和服务端权限边界，同时继续复用一个 React 构建、一个 FastAPI 应用、同一领域规则
和权威存储。

本次收口使用全新受管实例重新执行 `ops init`，并以管理员和客户两种角色完成真实浏览器验收。
活动数据目录的 Schema、迁移 Head、四类存储和前端资源均处于 Ready；原有未受管 SQLite 数据已
移出活动路径并保留在 Git 忽略的本地归档中，没有参与本次验收。

固定 Release Gate 在仓库外独立重放得到 `19/20`。唯一未完成项是当前机器没有 Docker，
`docker-compose-config` 按设计返回 `incomplete: docker_unavailable`。参考 Ubuntu 24.04 +
Docker Compose 的镜像与容器生命周期仍未验收，因此本报告不宣称参考部署完成。

## 产品结果

- 账号具有数据库持久化的 `customer | admin` 角色；自助注册和邀请码只能创建客户。
- 管理员只能通过本机 `admin grant|revoke|list` CLI 管理，既有 Session 会在请求时读取最新角色。
- 客户继续查看本人订单、服务、对话、审批和长期偏好，但不能写 Mock 订单、物流或支付事实。
- 管理员在 `/admin/data` 按显式目标客户维护同一业务 Repository，并产生脱敏后台审计。
- `/admin/invitations` 创建、查看和撤销邀请码；明文只在创建响应中展示一次。
- `/admin/runs` 只读投影既有 Run/Event 与有限 L2 诊断，不公开完整消息、Prompt 或隐藏推理。
- `/admin/eval` 准确区分 `missing`、`incompatible`、`failed` 和 `passed`，不会启动 Eval 或 Provider。
- `/admin/system` 与运营概览只公开有限版本、迁移、健康、Capability、存储和计数状态。
- 客户和管理员分别使用 `CustomerLayout` 与 `AdminLayout`；前端 Guard 只改善体验，API 仍是唯一授权依据。
- 客户空订单态只引导联系演示管理员，不再暗示客户具有 Mock 数据写权限。
- 邀请码在额度耗尽后明确显示“已用尽”；订单变更后客户订单计数会同步刷新。

## 本机浏览器验收

- 游客可以进入客户售后中心并使用 Fake 数据路径，不获得注册用户或后台权限。
- 客户可以登录、查看本人订单和进入对话入口；访问 `/api/admin/*` 返回 `403`，访问后台页面会被前端 Guard 导回客户表面。
- 管理员可以登录运营控制台，创建客户、Mock 订单和邀请码，并查看 Monitoring、Eval 与 System 只读状态。
- 管理员创建的 Mock 订单会出现在对应客户的订单列表；订单数、邀请状态和系统 Ready 状态与数据库一致。
- 客户表面与运营控制台共享同一后端，但导航、页面职责和授权边界保持分离。

## 安全与数据边界

- 游客和客户访问 `/api/admin/*` 不产生运营数据泄露或业务副作用。
- 管理员目标客户由服务端解析，不通过替换当前 Session 模拟客户。
- 管理员不能修改退款、Checkpoint、Memory、Agent Run 或 Eval Artifact。
- Monitoring 使用字段白名单，不连接完整消息正文；只读请求不会执行 Graph、模型、工具或审批。
- Eval Run ID 受限并在固定根目录解析；坏文件和路径逃逸安全降级。
- 系统状态不返回绝对路径、连接串、密钥或完整配置。
- `data/eval/runs/` 与 `var/` 都是 Git 忽略的运行产物；版本库只保存显式接受的脱敏 Baseline。

## 升级证据

代表性测试先把业务库降级至 v1.1 的 `20260722_0006`，创建客户、Session 和订单，再升级到
`20260722_0007`。升级后账号默认角色为 `customer`，原 Session 和订单保持可读；通过 CLI 等价
Repository 操作授予管理员后，既有 Session 立即解析为管理员；后台审计表存在且可写。

`data_format_version` 保持 `commerce-resolve-data-v1`，因为本次只增加角色字段和审计表，没有
改变四类数据库的职责、文件布局或恢复语义。

## 已知限制

- 订单、物流、支付、退款和 L2 Case 全部是本地 Mock/Fake，不连接真实外部系统。
- 运营控制台不是生产客服坐席或多租户 RBAC；没有客户模拟、真实人工接管和完整消息审阅。
- Eval、Provider Qualification、Baseline 接受、Backup、Restore 和 Upgrade 仍只允许固定本机 CLI。
- SQLite、单实例 BackgroundTask 和单 worker 只面向本地学习与作品集演示。
- 参考 Docker Gate 已延后；在支持环境补齐前，版本保持 Candidate。
