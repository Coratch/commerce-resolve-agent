## 评估范围

本报告验证 v0.8 的版本化 Eval Catalog、可复现 Run Artifact、显式 Baseline、Candidate
比较、真实 Provider 资格评测、故障归因和完整离线发布门禁。业务订单、物流、支付、退款和
L2 Case 继续使用项目内 Mock/Fake 数据；Provider 资格集只包含合成数据。

Offline Release Gate 与 Provider Qualification 是两条独立证据：前者证明确定性业务、安全和
工程回归，后者证明当前真实模型对结构化输出、工具参数和证据引用的适配质量，任何一条都不能
覆盖另一条失败。

## Eval Harness 故障注入

v0.8 的 40 条元场景覆盖：

- Catalog ID、Fixture、指纹、未知 Suite 和重复注册。
- Manifest 必填字段、可重复性、Git 状态与敏感字段。
- Baseline 接受、覆盖拒绝、取代关系和内容指纹。
- Candidate 的 fixed、removed、new failed 与 Schema 不兼容。
- Model、Fixture、Policy、Writer、Verification 和 Harness 失败归因。
- 工具、参数、终态、身份、Prompt Injection、退款、Replay 和零容忍安全门槛。
- Release 退出码、Git Ignore、报告投影和路径扫描。

正常运行结果为 `40/40`。强制注入一条安全违规时结果为 `39/40`，整个 Suite 失败，证明平均
通过率不能掩盖安全回归。

## 复现命令

```bash
conda activate ecom-agent

python -m commerce_resolve eval run \
  --output-root var/eval/runs \
  --run-id <candidate_run_id>

python -m commerce_resolve eval compare \
  --candidate var/eval/runs/<candidate_run_id> \
  --baseline data/eval/baselines/offline-v0.8.json

# 只有此命令读取 .env 并访问真实 Provider
python -m commerce_resolve eval qualify \
  --repetitions 2 \
  --output-root var/eval/runs

python -m commerce_resolve eval release \
  --baseline data/eval/baselines/offline-v0.8.json \
  --output-root var/eval/releases
```

Baseline 只在维护者审阅通过的 Candidate 后显式更新：

```bash
python -m commerce_resolve eval baseline accept \
  --run var/eval/runs/<candidate_run_id> \
  --output data/eval/baselines/offline-v0.8.json \
  --reason "说明接受原因"
```

## 已知限制

- Provider 资格会受模型服务版本、非确定性、网络和限流影响，不能替代离线门禁。
- 20 条 Provider 合成场景是小型资格集，不等同于线上流量、真实用户数据或统计显著性评测。
- v0.8 只提供本地 Artifact 和 Markdown 摘要，没有外部 Trace 平台、在线 Dashboard、A/B Test
  或自动回滚。
- 延迟和 Token 只报告，不作为当前小样本下的独立阻断指标。
- 测试仍有一条来自现有 FastAPI/Starlette 依赖的弃用警告，不影响本次通过结论。

## 结论

v0.8 的确定性 Offline Gate 和真实 Provider Qualification 均达到已接受门槛。现有 177 条业务
