# CommerceResolve v0.4 Mock 退款审批 Eval 报告

状态：Passed  
日期：2026-07-19  
场景集：`v0.4-refund-approval`

## 评估范围

本报告验证本地 Mock 整单退款的完整高风险链路：

- Mock 支付、退款动作、退款和审计事实的业务库持久化。
- 退款意图、订单号和原因的结构化提取及多轮补充。
- 基于最新订单、物流、支付、已有退款和当前政策的确定性资格判断。
- 带政策引用的 R2 预览、LangGraph `interrupt`、拒绝和跨进程恢复。
- 批准前重新校验、幂等执行、独立业务回读和完成声明。
- 过期预览、结果未知、验证不一致、重复请求、跨 thread 和权限攻击。
- React 审批交互、真实 FastAPI 同源服务及 Chromium 浏览器闭环。

离线门禁使用 Fake Interpreter、Fake Refund Gateway、固定日期、临时业务/Checkpoint/政策
数据库，不访问真实支付、电商或物流系统。DeepSeek 只完成独立结构化意图冒烟，不授权或
执行退款。

## 真实模型冒烟

使用 `.env` 中的 DeepSeek OpenAI-compatible Chat，只调用
`OpenAIQueryInterpreter.interpret()`：

```text
输入：请退款 ORD-001，商品有质量问题
输出：refund_request / ORD-001 / quality_issue
```

结果 `1/1` 通过。冒烟没有装配 Refund Gateway、没有调用审批恢复、没有写入 Mock 退款，
也没有记录 API Key、完整 Prompt 或模型隐藏推理。

## 数据与迁移

- 应用版本、FastAPI OpenAPI 和前端包版本均为 `0.4.0`。
- Alembic `20260717_0002_v04_refund_schema` 只新增交易表和索引，旧 v0.3 数据无需重建。
- 新业务表：`mock_payments`、`refund_actions`、`mock_refunds`、
  `refund_audit_events`。
- 金额 API 使用固定两位小数字符串，业务库使用整数 minor units，不使用浮点金额。
- 政策语料升级为 `2026-07-17-v2`，索引为 3 个文档、12 个章节、16 个事实；索引可重建。
- 旧订单没有 Mock 支付时仍可查询，但不能生成退款预览。
- 支付或退款事实存在后，删除订单会返回明确冲突，防止破坏审计链。

## 结论与限制

v0.4 在本地单实例范围内完成了“结构化退款诉求 → 确定性资格与预览 → 人工审批 →
幂等 Mock 写入 → 业务回读验证”的最小闭环，并达到所有固定发布门槛。

结果不能外推为真实资金、支付合规或生产并发能力。当前仅支持单笔 Mock 支付的整单退款，
受邀用户同时充当申请人与审批人；没有部分退款、逆向物流、多级审批、对账、外部通知或
人工客服 Handoff。
