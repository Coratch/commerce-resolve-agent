# CommerceResolve v0.5 AI 二线客服 Harness Eval 报告

状态：Passed

场景集：`v0.5-l2-support-harness`

## 评估范围

本报告验证明确披露为 AI 的二线客服完整受控链路：

- 注册用户升级预览、确认、取消与确认前零副作用。
- 严格结构化单步决策、固定 R0 Tool Registry 和有界 Agent Loop。
- 订单、物流、退款状态、政策与已确认偏好的可信 Observation。
- 信息补充、长期偏好和 Mock 退款三类独立中断与跨实例恢复。
- 长期偏好的建议、确认、拒绝、受限纠正和删除。
- L2 退款候选复用 v0.4 确定性资格、审批、幂等执行和回读验证。
- Case、公开 Trace、模型计量、身份隔离、Prompt Injection 与失败停止。

发布门禁使用 Scripted Fake L2 Model、临时业务数据库、临时 Checkpoint、独立
SqliteStore 和本地政策索引，不访问网络或真实外部系统。

## 真实 DeepSeek 安全冒烟

使用 `.env` 的 OpenAI-compatible Chat，只传合成订单号和 R0 Observation，不连接业务库、
不执行退款、不写长期记忆：

| 路径 | 结果 |
|---|---|
| 订单 + 物流多工具只读决策后回答 | 通过；模型先选择受控工具，证据齐全后形成回答 |
| 缺少订单号时返回 `ask_user` | 未通过；Provider JSON 未满足严格决策 Schema，Adapter 安全返回暂不可用 |

冒烟发现模型曾使用常见的 `call.parameters` 包装，而项目 Schema 要求 `call.order_id`。
系统指令已补充精确工具 JSON 契约、禁止重复工具和证据齐全后停止规则；Adapter 继续严格
拒绝未知字段，没有为单个 Provider 放宽安全边界。真实模型冒烟不参与离线 `30/30`
发布分数；缺信息决策的 Provider 兼容性留作后续模型/Prompt Eval 样本。

## 数据与迁移

- Python 包、FastAPI OpenAPI 和前端包版本均为 `0.5.0`。
- Alembic `20260719_0003_v05_l2_harness` 新增 L2 Case、公开事件和模型计量表。
- `var/memory.sqlite` 使用 LangGraph `SqliteStore` 独立初始化，不与业务 migration 合并。
- 业务库、Checkpoint、政策索引和 Memory Store 保持四类物理存储边界。
- L2 State 只保存可恢复 Runtime、预算、Observation 和引用，不保存完整 Prompt、密钥、
  数据库连接或隐藏推理。

## 结论与限制

v0.5 在本地单实例范围内完成了“用户确认升级 → 结构化多步决策 → Policy 与 R0 工具 →
Observation → 补充信息/长期偏好/退款审批 → 公开 Case Trace”的最小闭环，并达到全部离线
发布门槛。

结果不能外推为生产客服系统或真实人工坐席。当前只有单个 AI Agent、固定同步 HTTP
请求、有限 R0 工具和受限枚举记忆；没有多 Agent、任意网络工具、异步 Worker、Token 级
SSE、真实支付或真实客服 Handoff。真实 DeepSeek 的缺信息决策仍需后续兼容性 Eval。
