# Feature Spec：v2.0.1 意图澄清循环

状态：Accepted / Implemented  
日期：2026-07-24  
依赖版本：v2.0 可演示、可评估的智能售后 Agent 产品

## 目标

当一级 Agent 无法可靠识别用户意图时，不再把请求当作系统异常，也不猜测高影响动作；系统在
同一订单 Thread 中发起最多两轮意图澄清。用户补充后重新经过结构化意图识别，识别成功则进入
既有订单、物流、政策、退款或 AI 深度处理路径；连续两轮澄清后仍无法识别，则返回明确兜底话术
并结束本次澄清。

## 第一性原则

1. 无法理解是正常对话状态，不是模型或系统故障。
2. 澄清只收集意图，不调用订单、物流、政策、退款或 L2 工具。
3. 模糊表达不能被自动解释为退款等高影响动作。
4. 澄清次数必须由服务端 State 记录，不能依赖 Prompt 或前端计数。
5. 每条用户补充仍是一轮独立模型调用，沿用现有额度和审计规则。

## 用户行为

- 首次返回 `unknown` 时，助手列出当前可处理的主要诉求并等待用户补充。
- 第二次仍返回 `unknown` 时，助手给出更具体的编号选项并再次等待。
- 第三次仍返回 `unknown` 时，助手返回兜底话术，状态变为 `intent_unresolved`，并清空计数。
- 任一澄清轮识别成功后，立即清空计数并进入既有安全路径。
- “退库”等无法区分退货与退款的表达必须进入澄清，不能直接执行 Mock 退款。
- `unsupported_write` 表示已经识别但产品不支持的明确动作，不进入澄清循环。
- Provider 不可用、输出违反 Schema、权限失败和额度耗尽仍使用既有错误路径，不计入澄清次数。

## 技术边界

- 澄清是跨用户轮次的持久化逻辑循环：

  ```text
  START
    → bind_and_interpret
    → unknown
    → clarify_intent
    → END（等待下一条用户消息）
    → START
  ```

- 不使用 `interrupt()` 获取普通聊天输入，避免与退款审批和 L2 恢复协议混用。
- 不增加新数据库表；次数保存在 LangGraph Checkpoint 的 `AgentState` 中。
- 不新增退货、换货、取消订单、修改地址或真实退款能力。
- 前端继续把澄清和兜底显示为普通助手消息，不新增错误卡或审批卡。

## 验收条件

1. 首次未知意图返回 `awaiting_intent_clarification`，澄清次数为 `1`。
2. 第二次未知意图仍返回等待状态，澄清次数为 `2`。
3. 第三次未知意图返回 `intent_unresolved`，次数重置为 `0`。
4. 澄清后识别为有效意图时进入既有路径并重置次数。
5. 澄清过程不会调用订单、物流、政策、退款或 L2 工具。
6. SQLite 关闭并重新打开后仍能恢复澄清次数。
7. Web 返回 `200`，澄清内容持久化为普通助手消息，刷新后仍可读取。
8. 明确退款继续进入既有 Policy、审批和幂等 Mock 退款链。
9. 明确不支持的写操作继续使用能力边界回复，不消耗澄清次数。
10. 新增固定模糊输入场景，未经澄清或批准的退款数量为 `0`。
