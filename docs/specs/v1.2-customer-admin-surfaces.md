# Feature Spec：v1.2 客户售后中心与 Agent 运营控制台

状态：Accepted  
日期：2026-07-22  
接受日期：2026-07-22  
依赖版本：v1.1 订单优先的智能售后中心（当前为 Candidate）  
关联决策：ADR-0012

## 目标

客户进入 CommerceResolve 后，只围绕本人订单、物流、服务进度、政策依据、审批和上下文助手完成
售后任务；项目管理员进入独立的 Agent 运营控制台，准备 Mock 业务数据、管理邀请、观察脱敏
Agent Run，并查看版本化 Eval 与有限系统状态。

v1.2 成功不是增加一个带图表的 `/admin` 页面，而是建立可验证的角色、权限和信息边界：客户不再
承担演示数据准备职责，管理员也不能借运营界面绕过业务 Policy、审批、数据归属或审计。两个产品
表面继续复用同一个模块化单体、领域规则和权威数据，不拆分后端服务。

## 第一性原则

1. **界面服务角色任务。** 客户解决售后问题，管理员准备演示数据并判断 Agent 是否可靠运行。
2. **后台入口不等于后台权限。** 菜单隐藏、路由守卫和不可猜测 URL 不能代替服务端授权。
3. **运营控制台不是万能后门。** 后台写操作仍受业务约束、审计和数据生命周期限制。
4. **Monitoring 与 Eval 分离。** Monitoring 观察真实 Run；Eval 使用固定数据集验证候选版本。
5. **分离产品表面，不复制业务核心。** 前后台读取同一权威事实并复用相同 Policy、工具与验证规则。
6. **内部可见性仍需最小化。** 排障价值不能成为公开密钥、完整 Prompt、隐藏推理或跨用户正文的理由。

## 角色

### 游客

- 使用客户售后中心中的共享只读演示订单和确定性 Fake 模式。
- 不能进入运营控制台、管理 Mock 数据、读取 Monitoring/Eval 或触发真实 LLM。

### 注册客户

- 在客户售后中心查看本人私有演示订单、服务进度、公开会话、政策依据和待办动作。
- 可以按既有权限使用 LLM、审批本人 Mock 退款、管理本人长期偏好和恢复会话。
- 不再创建、修改或删除 Mock 订单、物流和支付事实。

### 管理员

- 通过受控本机入口显式创建或授予，不能通过邀请码、自助注册、前端字段或模型输出获得权限。
- 可以进入 Agent 运营控制台，按本 Spec 管理演示数据、邀请并读取脱敏运营信息。
- 可以使用自己的身份访问客户售后中心进行产品预览，但不能模拟、接管或冒充其他客户。
- 管理员权限不允许绕过退款 Policy、审批、幂等执行、结果验证或高影响运维入口。

### 项目维护者

- 继续通过固定 CLI 完成完整 Eval、Provider Qualification、Backup、Restore、升级和 Reconcile。
- v1.2 不假设管理员与宿主维护者必然是同一真实人员，也不把 Web 管理员升级为宿主权限主体。

## 产品表面

### 客户售后中心

客户侧继续提供：

- 售后首页、本人订单与物流、服务进度和政策依据。
- 绑定订单或服务目标的上下文助手。
- Mock 退款预览、明确审批、结果回读和 AI 二线客服。
- 公开会话历史、待办恢复和本人长期偏好。
- 面向客户的业务证据、处理状态、下一步动作和明确降级信息。

客户侧不再提供：

- Mock 订单、商品、物流或支付事实的创建、修改和删除入口。
- 邀请码、账号运营、Eval、Baseline、Provider、Token、内部节点或系统健康入口。
- 面向开发者的 Context Manifest、失败归因、完整 Agent Run 或内部工具参数。

客户仍可看到与本人结论直接相关的政策引用、公开服务时间线和必要处理依据；移除内部诊断不能
删除或弱化这些客户证据。

### Agent 运营控制台

运营控制台至少组织为以下产品能力，具体页面、API 和组件由 Technical Plan 决定。

#### 运营概览

- 展示有限的 Mock 用户、订单、进行中服务和 Agent Run 聚合状态。
- 展示当前版本、Capability 和最近 Eval 摘要。
- 聚合计数必须来自服务端权威存储或版本化 Artifact，缺失时显示明确不可用，不补造数字。

#### 演示数据管理

- 管理员可以选择一个注册客户，为其创建或维护 Mock 订单、最小商品行、物流和退款前支付事实。
- 管理员可以查看该客户已有的退款与售后服务结果，但不能直接覆盖这些权威结果。
- 现有订单冲突、支付锁定、退款后限制和删除依赖规则继续有效。
- 后台修改成功后，客户页面与 Agent 下一次工具查询必须读取到同一最新业务事实。

#### 邀请与账号

- 管理员可以创建具有有效期和使用次数的注册邀请码、查看有限使用状态并撤销邀请码。
- 邀请码明文只在创建结果中展示一次，之后不从存储或页面重新读取。
- 后台只展示完成演示数据准备所需的有限客户标识和账号状态。
- v1.2 不提供密码查看、客户身份模拟、任意 Session 撤销或从 Web 授予管理员权限。

#### Agent Monitoring

- 管理员可以按有限条件查看真实 Agent Run 的状态、类型、时间、步骤数、工具类别、停止原因、
  Provider 延迟/用量、Policy/审批结果和确定性失败归因。
- Run 详情只展示脱敏、结构化且有排障价值的事实，不默认展示完整用户消息正文。
- Monitoring 读取不得执行 Graph、模型、工具、Memory 写入或 Mock 退款副作用。
- v1.2 Monitoring 只读，不允许管理员替客户重试、恢复、批准、拒绝或取消任务。

#### Agent Eval

- 展示可用 Eval Suite、当前已接受 Baseline、最近 Candidate、分能力结果、安全违规和回归差异。
- Eval 结果必须标识数据集、代码、模型/Prompt、工具和运行配置版本；缺失或不兼容时明确说明。
- 后台只读取已经生成的版本化 Artifact，不能在 Web 请求中启动完整 Eval 或 Provider Qualification。
- 真实 Monitoring 数据不会自动成为 Eval 样本，也不能替代固定发布门禁。

#### 系统状态

- 只读展示版本、迁移、Live、Ready、Capability、权威存储和派生政策索引的有限状态。
- 不公开密钥、Cookie、绝对路径、完整日志或未经脱敏的配置。
- Backup、Restore、Upgrade、Reconcile 和其他高影响运维继续使用固定 CLI。

## 身份与授权

- 服务端 Session 必须包含或能够解析稳定的后台授权能力；前端自报角色没有授权效力。
- 客户与运营 API 使用明确、可测试的权限边界，不允许复用“任意注册用户可写本人数据”的旧判断
  作为后台授权。
- 管理员访问指定客户数据时必须使用显式目标、服务端验证和审计，不允许把目标客户伪装成当前
  Session 身份。
- 不存在、无权限和已删除目标使用不泄露额外资源信息的稳定错误语义。
- 管理员会话继续执行 CSRF、Origin、限流、过期、撤销和 Cookie 安全规则。
- 客户身份访问任何运营数据或后台写接口产生的数据泄露与副作用数量必须为 `0`。

## 数据、隐私与审计

- 客户、管理员、业务数据、Checkpoint、Memory、政策索引、Audit 和 Eval 继续保持既有存储职责。
- 运营控制台不创建第二套订单、退款、Case、Agent Run 或 Eval 事实。
- 后台业务写入记录管理员标识、目标客户/工作区、动作、脱敏参数、结果和时间。
- Monitoring/Eval 响应不得包含 API Key、Cookie、完整 Prompt、模型隐藏推理、未脱敏工具输出或
  默认完整客户消息正文。
- 页面刷新和路由切换只重新读取状态，不启动 Agent、模型、工具、完整 Eval 或业务写入。

## 兼容与迁移

- 现有注册账号迁移为普通客户；管理员必须通过受控本机入口显式授予。
- 现有账号、Session、工作区、订单、物流、支付、退款、Conversation、消息、Agent Run、
  Checkpoint、L2 Case、Memory、Audit 和 Eval Artifact 保持可读。
- 已有客户私有 Mock 订单继续属于原客户并可用于售后；客户只失去后续演示数据维护权限。
- 原演示数据入口对非管理员不得继续执行写操作；旧书签或直接请求不能绕过新权限。
- 客户售后、审批、SSE、恢复和既有公开 URL 保持兼容。
- 数据或角色迁移失败时实例保持非 Ready，不通过默认管理员或放宽权限绕过。

## 错误与降级语义

| 场景 | 用户可观察结果 |
|---|---|
| 游客或客户访问运营控制台 | 返回稳定无权限结果，不泄露后台是否存在具体资源 |
| 前端伪造管理员角色 | 服务端拒绝，后台读取、模型调用和业务写入数量均为 `0` |
| 管理员目标客户不存在或不可访问 | 使用统一目标不可用语义，不执行部分写入 |
| Mock 数据违反既有业务约束 | 返回明确业务冲突，客户原数据保持不变 |
| Monitoring 数据缺失或损坏 | 显示有限不可用状态，不运行任务补造 Trace |
| Eval Artifact 缺失或不兼容 | 显示未产生或不兼容，不把旧结果冒充当前结果 |
| Readiness 非就绪 | 后台展示有限状态和稳定失败码，不提供绕过操作 |
| 客户仍访问旧演示数据入口 | 安全引导至客户页面或拒绝；不会继续写入 |

## 版本范围

v1.2 包含：

- 客户售后中心与 Agent 运营控制台的导航、内容和权限分离。
- 单一管理员能力、受控授予和服务端后台授权。
- 客户 Mock 数据维护权限迁移到后台。
- 管理员的 Mock 订单、商品、物流、退款前支付及邀请管理。
- 脱敏、只读的 Agent Monitoring、Eval 和系统状态视图。
- 现有数据和客户路径的兼容迁移。
- 前后台越权、脱敏、只读副作用和 Eval Artifact 的固定自动化场景。

## 非目标

v1.2 不包含：

- 第二个后端服务、微服务、独立前端仓库或 credentialed CORS。
- 真实电商、支付、物流、CRM、客服坐席或身份系统接入。
- 客服队列、坐席分配、SLA、内部备注、班次或真实人工接管。
- 管理员模拟客户、查看密码、默认读取完整消息正文或从 Web 授予管理员权限。
- 在 Web 中启动完整 Eval、Provider Qualification、Backup、Restore、升级或任意 Shell。
- 修改 Prompt、工具注册表、Agent 图、Policy 源码、数据库记录或 Eval Baseline 的通用编辑器。
- 新售后类型、退货/换货/取消、部分退款、逆向物流或真实资金操作。
- 多租户 SaaS、套餐计费、多实例、高可用、后台 Worker 或消息队列。
- 为运营控制台新增第二套订单、退款、Case、Trace 或 Eval 数据源。

## 验收条件

1. 客户主导航和客户页面不再展示演示数据管理、Eval、Monitoring 或系统运维入口。
2. 游客和普通客户访问运营页面与全部运营 API 均被服务端拒绝，运营数据泄露数量为 `0`。
3. 修改前端状态、请求字段、Cookie 非敏感内容或直接访问 URL 不能获得管理员权限。
4. 管理员只能通过受控本机入口显式创建或授予；邀请码和自助注册不能产生管理员。
5. 管理员可以创建、查看和撤销邀请码；邀请码明文不会在创建后的读取响应中再次出现。
6. 管理员可以选择注册客户并为其创建或维护 Mock 订单、最小商品行、物流和退款前支付事实。
7. 后台写入继续遵守订单冲突、支付锁定、退款后限制、删除依赖和审计规则。
8. 管理员成功修改业务事实后，客户页面和 Agent 下一次查询读取到相同最新结果。
9. 普通客户不能继续通过旧 Web API 或旧页面创建、修改或删除 Mock 业务数据。
10. 现有客户账号、订单、会话、消息、退款、Checkpoint、L2 Case 和 Memory 迁移后保持可读。
11. 管理员可以查看脱敏 Agent Run 列表，并按有限状态、类型和时间条件定位运行记录。
12. Run 详情展示结构化步骤、工具类别、停止原因、延迟/用量及失败归因，不公开被禁止内容。
13. 浏览 Monitoring 不执行 Graph、模型、工具、Memory 写入、审批或 Mock 退款副作用。
14. 管理员可以查看当前 Eval Baseline、最近 Candidate、分组结果、安全违规和兼容性结论。
15. Eval 页面准确区分无 Artifact、Artifact 不兼容、Candidate 失败和通过四类状态。
16. 浏览 Eval 不创建 Eval Run、不调用 Provider，也不能接受或修改 Baseline。
17. 管理员可以查看有限版本、迁移、健康、Capability 和存储状态，但不能从 Web 执行高影响运维。
18. 客户和运营表面继续由同一个 FastAPI 部署单元、同源 Web 构建和共享领域核心提供。
19. 管理员不能覆盖退款事实、绕过 Policy/审批或直接修改 Checkpoint、Memory 和 Eval 结果。
20. 客户侧订单、服务、对话、退款审批、SSE、恢复和长期偏好行为保持兼容。
21. 客户界面继续满足桌面、移动端、键盘、焦点和 Reduced Motion 的既有验收边界。
22. 运营界面的加载、空状态、无权限、数据损坏和系统非就绪均使用可理解产品状态，不暴露内部异常。
23. 新增固定场景覆盖正常后台操作、匿名/客户越权、角色伪造、跨客户数据、脱敏、只读副作用、
    Artifact 缺失/不兼容和既有客户回归。
24. 全量自动化测试、Offline Eval 和安全门禁保持通过，未授权业务写入和敏感字段泄露均为 `0`。
25. README、目标地图、代码职责、运行说明和已知限制与最终实现一致。

## 已接受产品决策

1. 普通注册客户不再维护 Mock 订单、物流和支付事实；这些演示数据由管理员在运营控制台准备。
2. 管理员只能通过受控本机入口显式授予，不能由邀请码注册、前端字段或模型产生。
3. Agent Monitoring 默认不展示完整用户消息，只展示脱敏、结构化且有排障价值的运行事实。
4. Agent Eval 控制台只读；完整 Eval、Provider Qualification 和 Baseline 接受继续使用固定 CLI。
5. 客户与运营表面继续使用同一个 React/FastAPI 模块化单体，不拆分后端服务。
