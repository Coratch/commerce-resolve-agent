# Feature Spec：v1.4 多模态政策知识与复杂问答

状态：Superseded  
日期：2026-07-23  
依赖版本：v1.3 商业化售后中心与智能服务体验  
取代原因：项目于 2026-07-24 决定先以 v2.0 完成邀请制售后 Agent 产品重构；本 Spec 的
多格式、多模态与向量检索目标重新排入 v2.1，历史内容保留用于后续规格输入。  

## 目标

把 CommerceResolve 现有“受控 Markdown 政策 + SQLite FTS5”的政策问答能力扩展为可管理的
多格式、多模态政策知识能力。管理员可以导入、检查并显式发布本地政策文件；客户和 AI 二线
客服可以针对口语化、跨文档、多条件以及依赖表格或扫描页面的问题，获得有当前版本、页码或
元素位置的可验证回答。

v1.4 必须引入独立、可重建的向量检索能力，但向量相似度不是政策事实、政策版本或业务授权。
系统仍需保留精确检索、确定性元数据过滤、证据充分性检查和引用校验，并使用固定 Eval 证明
语义/多模态检索相对 v0.2 FTS5 基线解决了真实漏召回问题。

本版本不改变订单、物流、支付和退款均为本地 Mock/Fake 数据的产品边界，也不允许政策检索、
LLM 或多模态模型决定退款资格、金额、渠道和审批要求。

## 第一性原则

1. **用户需要的是可验证结论，不是相似文本。** 向量得分只能选择候选证据，不能证明政策适用。
2. **原始已发布文件是政策事实来源。** 解析文本、OCR、摘要、Chunk 和向量均为可重建派生数据。
3. **多格式不等于多模态。** 文本型 PDF 应优先直接解析；只有信息存在于扫描图、表格或视觉布局时才使用 OCR 或视觉表示。
4. **精确与语义检索互补。** 条款编号、天数、金额和商品名优先精确匹配，口语和同义表达由语义检索补充。
5. **先过滤适用范围，再形成结论。** 发布状态、生效时间、区域、商品类别和版本不能由相似度排序替代。
6. **复杂问题需要有界分解。** 系统可以拆分子问题、再次检索和请求澄清，但循环次数、证据数和模型预算必须受限。
7. **每个关键结论都必须绑定证据。** 引用必须能够回到确定文件、版本、页码、章节、表格单元或图片区域。
8. **知识发布必须显式。** 文件上传、解析或模型抽取成功不等于政策已发布，未经管理员确认的内容不能面向客户生效。
9. **检索与授权分离。** RAG 负责提供政策证据，确定性 Policy 负责退款资格与资金边界，LLM 负责理解和解释。
10. **向量能力必须由 Eval 证明。** 如果新链路不能改善语义/多模态召回，不能用“已接入向量数据库”代替用户价值。

## 术语

| 术语 | 定义 |
|---|---|
| Policy Source | 管理员导入的一份原始政策文件及其来源元数据 |
| Source Version | 同一政策来源的一次不可变内容版本，具有稳定 ID、内容 Hash、生效范围和生命周期状态 |
| Policy Element | 从源文件解析出的标题、段落、列表、表格、图片文字或视觉区域 |
| Evidence Unit | 可独立支持结论、具有稳定 ID 和原文件定位信息的最小证据单元 |
| Derived Index | 由已发布 Source Version 生成、可以删除并重建的全文或向量索引 |
| Hybrid Retrieval | 同时使用精确/全文检索与语义向量检索，并以确定性方式融合和过滤结果 |
| Multimodal Evidence | 语义依赖图片、扫描页面、表格结构或视觉布局，不能只由普通正文文本完整表达的证据 |
| Complex Policy Question | 需要多个条件、多个证据、多个来源或订单事实与政策事实组合才能回答的问题 |
| Evidence Pack | 提交给回答节点或 L2 模型的有限、结构化、带引用候选证据集合 |

## 角色与权限

### 游客

- 继续使用共享、只读演示工作区和确定性 Fake 路径。
- 可以查询当前已发布的演示政策并查看有限引用。
- 不能上传、解析、发布、撤回或重建政策来源和索引。
- 不能通过文件名、引用或查询枚举未发布来源。

### 注册客户

- 可以在本人订单或服务上下文中查询当前已发布政策。
- 可以查看支持当前回答的标题、版本、生效信息、页码/章节和安全预览。
- 不能上传或修改政策，也不能访问原始文件中的内部元数据、解析诊断或其他用户正文。
- LLM 权限继续由服务端确定；向量检索本身不能扩大模型或业务权限。

### 管理员

- 可以在 Agent 运营控制台导入白名单格式的本地政策文件。
- 可以查看文件 Hash、版本、生效范围、解析状态、警告、元素预览和索引状态。
- 可以在确认解析结果后显式发布新版本，或把旧版本标记为已取代。
- 可以对单个来源触发幂等重试、重建派生索引和查看有限失败原因。
- 不能通过 Web 执行任意文件解析命令、任意模型 Prompt、任意路径读取或完整离线 Eval。

## 核心用户旅程

### 旅程 A：导入并发布多模态政策

1. 管理员选择受支持的本地政策文件并填写标题、区域、生效时间和政策主题。
2. 系统验证类型、大小、Hash 和重复版本，不执行文件中的脚本、宏、链接或指令。
3. 系统解析正文、页面、表格和需要 OCR 的区域，形成可预览的 Policy Element。
4. 管理员看到解析警告、低置信 OCR、无法定位元素或重复内容。
5. 管理员明确确认后发布该 Source Version。
6. 只有发布成功且索引与来源版本一致的证据才能用于确定性政策回答。

### 旅程 B：口语化政策查询

1. 用户询问“东西已经拆开了，还能不要吗”等不包含政策原词的问题。
2. 系统识别政策主题和已知条件，同时保留原始表达。
3. 混合检索同时覆盖精确条款与语义相近证据，并先约束当前发布版本、区域和生效时间。
4. 系统校验证据是否直接支持结论；证据充分时返回有定位引用的回答。
5. 语义候选与精确证据不一致时不能按向量分数静默选择。

### 旅程 C：从扫描页或表格回答

1. 用户询问的问题对应扫描政策页或商品类别表格中的条件。
2. 系统可以召回 OCR 文本、表格行列或关联视觉区域。
3. 回答展示政策文件、版本、页码以及表格/区域定位，并允许查看安全预览。
4. OCR 或表格结构不足以支持关键结论时，系统说明证据质量不足，不把相似页面当作确定事实。

### 旅程 D：跨文档、多条件复杂问答

1. 用户从绑定订单提出“耳机拆封且签收十天，左耳无声，能退还是只能换”等问题。
2. 系统分别取得最新订单事实、用户提供条件和当前适用政策证据。
3. 系统可以把问题拆成期限、商品例外、质量问题和处理流程等有限子问题。
4. 每个子结论保留自己的证据；缺失条件触发最小澄清，冲突证据触发冲突状态。
5. 系统输出事实、政策结论、缺失/冲突、建议和允许动作；退款资格和金额仍交给确定性 Policy。

### 旅程 E：版本冲突与安全降级

1. 当前发布政策之间出现无法由版本、生效期、区域或优先级消解的冲突。
2. 系统展示冲突主题和双方引用，不要求 LLM选择“更合理”的一方。
3. 向量索引不可用、版本落后或内容 Hash 不一致时，系统不使用该索引形成确定结论。
4. 精确检索仍有充分证据时可以按受控降级回答；否则明确证据不足并建议稍后重试或升级 AI 二线客服。

## 政策来源范围

v1.4 最小支持以下受控来源：

- 现有 Markdown/JSON 政策语料。
- 含可提取正文的 PDF。
- 主要由扫描图片构成的 PDF。
- PNG/JPEG 政策图片。
- 同时包含正文、列表、图片和表格的 PDF。

每个 Source Version 至少记录：

- 稳定来源 ID 和不可变版本 ID。
- 原始文件名、安全媒体类型、字节数和内容 Hash。
- 标题、主题、区域、发布时间、生效起止时间和发布状态。
- 导入时间、解析状态、索引状态和有限错误代码。
- 原始文件与派生元素的版本关联。

来源处理规则：

- 文件类型使用内容检测和白名单校验，不能只相信扩展名或浏览器声明。
- 损坏、加密、密码保护、超出限制或类型不一致的文件安全拒绝。
- 不执行 PDF/图片中的链接、JavaScript、附件、宏、外部引用、Prompt 或工具指令。
- OCR 只在普通文本提取无法覆盖必要内容时执行，并保留识别方式与置信信息。
- 表格必须保留行列关系和来源坐标；不能只把所有单元格拼成无结构字符串。
- Source Version 一经发布不可原地改写；内容变化必须创建新版本。
- 重复文件或重复版本使用内容 Hash 幂等识别，不重复生成有效政策版本。
- 原始二进制、页面图片、OCR 正文和向量不得进入 LangGraph State、Checkpoint、公开消息或日志。

## 来源生命周期

来源至少具有以下可区分状态：

```text
draft
→ processing
→ ready_for_review
→ published
→ superseded

processing → failed
```

- `draft`、`processing`、`ready_for_review`、`failed` 来源不能被客户检索。
- 只有管理员显式确认才能从 `ready_for_review` 进入 `published`。
- 发布前必须确认派生索引引用相同 Source Version 和内容 Hash。
- `superseded` 版本不参与新的当前政策查询，但历史引用仍需能说明原版本和失效状态。
- 删除原始来源、清理历史版本和撤回政策属于独立高影响操作；v1.4 不提供不可追溯的硬删除。

## 元素、切分与引用行为

- Policy Element 必须保留文档层级，至少区分标题、段落、列表、表格、图片/OCR 区域。
- Evidence Unit 以政策语义和可引用位置为边界，不能仅按固定字符数跨标题或跨表格行切分。
- 单个证据可以包含有限上下文，但必须明确哪个事实直接支持回答。
- 每个 Evidence Unit 具有稳定 ID、内容 Hash、Source Version、页码/章节和适用时的区域坐标。
- 同一事实来自正文与表格时可以关联，但不能重复计数制造虚假证据充分性。
- 引用至少可以解析为：标题、版本、生效信息、页码或章节、证据摘要和原始位置。
- 客户预览只返回完成回答所需的有限区域，不默认公开整份原始文件或内部解析产物。

## 检索行为

### 召回时机

- 一线流程识别为政策问题或 v1.3 组合咨询包含政策/退款资格时，必须执行受控政策检索。
- 单纯订单或物流查询不因 v1.4 自动引入政策召回。
- L2 Agent 可以通过现有白名单 `search_policy` 工具按需检索，但工具仍受相同发布、版本、过滤和预算约束。
- 涉及退款资格的流程必须获取确定性 Policy 所需的当前事实，模型不能选择跳过必要检索。

### 混合召回

- 在线检索必须保留精确/全文检索，并增加独立向量语义检索能力。
- 候选结果融合前后都必须保持 Source Version、发布状态、区域、生效时间和政策主题约束。
- 条款编号、期限、金额、商品 SKU/类别等精确匹配不能被较高语义相似度覆盖。
- 多模态向量只用于需要视觉语义的证据；普通文本不得为了展示技术而强制转换成页面图片检索。
- 融合、Rerank、Top-K、分数门槛和各检索预算由 Technical Plan 定义，并纳入版本化 Eval 配置。
- 检索结果必须去重并保留各召回通道、排名、适用过滤和版本信息，便于失败归因。

### 复杂问题与有界循环

- 系统可以对一个复杂问题生成有限、结构化的子查询，但子查询不能改变用户身份、订单绑定或政策适用范围。
- 每个子问题必须对应明确主题或缺失条件，不能进行开放式研究或联网检索。
- 检索不足时最多进行有限次数的查询改写/补充检索；具体上限由 Plan 固定并进入 Eval。
- 证据充分后停止检索；缺少用户条件时优先澄清，不能用更多相似结果替代缺失事实。
- 相互冲突的有效证据不能被 Rerank 分数、模型偏好或多数票自动消解。

## Evidence Pack 与回答行为

提交给回答节点或 L2 模型的 Evidence Pack 只能包含当前任务需要的有限内容，至少包括：

- 用户问题和经过服务端验证的订单/服务上下文引用。
- 已知条件、缺失条件和冲突说明。
- 每个证据的 `evidence_id`、支持事实、来源 ID、版本、生效信息和定位。
- 检索通道与必要的新鲜度/完整性标识。
- 本次允许模型执行的有限动作和预算。

回答规则：

1. 每个影响期限、费用、适用范围、例外或下一步的关键结论必须绑定有效 `evidence_id`。
2. LLM 只能根据 Evidence Pack 解释和组织答案，不能引用未入包来源或使用模型记忆补充政策事实。
3. 一线确定性政策回答可以继续不调用 LLM；引入向量检索不强制把所有答案改为生成式回答。
4. 表格或图片证据必须转换为可验证事实并保留原位置，不能只把图片描述当作政策原文。
5. 证据不足进入明确拒答或澄清状态；政策冲突展示双方来源，不生成单一确定结论。
6. L2 Agent 的政策 Observation 继续使用有限摘要和证据 ID，不把整份文件、页面图片或全部 Top-K 塞入 Context Pack。
7. 回答只能建议进入既有退款预览；资格、金额、渠道、风险、审批和执行继续由确定性代码决定。

## 客户体验

- 客户从订单、服务或上下文助手提出复杂政策问题时，不需要重复提供已绑定且服务端验证的订单号。
- 回答公开区分已验证业务事实、政策证据、缺失条件、冲突、建议、允许动作和下一步。
- 文本来源显示标题、版本、章节/页码；表格/图片来源增加元素类型和安全区域预览。
- 用户可以从引用查看必要上下文，但不能借引用读取未发布来源、解析目录或服务器绝对路径。
- 解析中、索引中、检索降级、证据不足和模型不可用使用正常客服/任务语义，不显示技术堆栈或数据库名称。
- 刷新、切页、断线和重新登录继续通过公开消息、Run/Event 和 Checkpoint 恢复，不重新上传或重复索引文件。

## Agent 运营控制台体验

- 管理员可以查看来源列表、版本、生效状态、文件类型、解析/索引状态和最近更新时间。
- 导入页面只接受白名单文件，并在提交前展示类型、大小、政策主题和生效范围。
- Review 页面展示结构化元素、页码、表格/图片标记、OCR 警告和无法定位内容。
- 发布动作明确展示来源版本、适用范围、影响和当前版本取代关系。
- 管理员可以触发单一来源的受控重试或派生索引重建，但不能修改向量、执行任意查询或启动无界任务。
- 运营页面只展示有限检索诊断和 Eval 摘要，不公开完整客户问题、模型 Prompt、API Key 或服务器路径。

## 事实、安全与权限

- 已发布、当前适用的原始 Source Version 是政策事实来源；解析、OCR、向量、Rerank 和 LLM 输出均为不可信派生数据。
- 文件正文、OCR 文本、图片和元数据中的 Prompt Injection 不能改变系统指令、过滤、工具或权限。
- 管理员上传权限不能通过前端字段、邀请码、模型输出或客户会话获得。
- 文件解析必须限制类型、大小、页数、像素、处理时间、并发和输出规模；超限时安全失败。
- 向量索引、全文索引、来源目录、业务库和 Checkpoint 必须具有独立生命周期与路径。
- 云端 Embedding、OCR 或多模态 Provider 如果在 Plan 中被选择，必须明确哪些文件内容离开本机；密钥不得进入索引 Payload、Checkpoint、日志或 Artifact。
- 客户问题和私有订单上下文不得写入共享政策索引。
- 检索、预览、发布、取代和重建操作必须记录脱敏审计，不能记录完整敏感文件正文。
- 未经批准的 Mock 退款、重复退款、真实外部副作用和跨用户数据读取数量必须为 `0`。

## 错误与降级语义

| 场景 | 用户或管理员可观察结果 |
|---|---|
| 文件类型不支持、损坏或加密 | 导入失败并显示稳定原因，不创建可发布版本 |
| 文本提取为空但可 OCR | 标记 OCR 处理方式和警告，完成后进入 Review |
| OCR/表格无法可靠定位 | 保留警告；不能用该元素支持确定性关键结论 |
| 向量生成或索引失败 | 来源不进入可用发布状态，或保持上一已发布版本继续服务 |
| 向量索引版本落后 | 不使用陈旧向量；精确证据充分时受控降级，否则拒答 |
| 精确与语义候选冲突 | 进入证据检查；不按单一分数自动选择 |
| 当前证据不足 | 请求最小补充信息或明确无法确认 |
| 当前有效政策冲突 | 展示冲突点和双方引用，建议升级处理 |
| 引用对应文件或 Hash 变化 | 引用校验失败，不输出该关键结论 |
| 模型不可用 | 仍可使用受控确定性回答；需要生成式处理时显示普通客服降级状态 |
| 重建过程被中断 | 已发布旧索引保持可用或整体失败回滚，不暴露半成品索引 |

## 兼容与迁移

- v0.2 的 Markdown/JSON 政策、稳定政策事实、引用和 FTS5 行为继续可读并作为检索基线。
- v1.3 的组合咨询公开 Schema、订单绑定、退款链、L2 工具和会话恢复语义保持兼容。
- 新 Source Version、Policy Element 和 Evidence Unit 不能静默改写既有事实 ID；需要映射时由 Plan 定义显式迁移。
- 向量索引是可重建派生数据，不与业务数据库、Checkpoint 或长期记忆共享表或备份语义。
- 发布新政策导致 Corpus Hash 或确定性退款事实变化时，既有待审批预览继续按 v0.4 规则失效并重新生成。
- 现有历史消息和引用保留原版本信息；旧版本被取代后不能伪装成当前政策。
- 向量能力不可用时，现有精确政策问答、订单、物流、退款审批和 L2 Case 不能发生越权或数据损坏。
- 如果新增长期存储、独立进程、模型边界或文件解析信任边界，Technical Plan 必须提出 ADR 和迁移/备份策略。

## 版本范围

v1.4 包含：

- 管理员导入、预览、显式发布和取代本地受控政策来源。
- Markdown/JSON、文本 PDF、扫描 PDF、PNG/JPEG 和含表格 PDF 的最小来源集合。
- 具有页码、章节、表格/图片区域和内容 Hash 的统一 Evidence Unit。
- 保留全文检索并新增独立、可重建的向量语义检索能力。
- 元数据过滤、混合召回、证据去重、充分性检查和冲突处理。
- 口语化、跨文档、多条件、订单绑定和多模态复杂政策问答。
- 有限 Evidence Pack、可定位引用和客户安全预览。
- 运营控制台的来源生命周期、解析/索引状态和有限诊断。
- 固定多模态 RAG Eval、现有 FTS5 基线比较、Provider 资格与安全回归。

## 非目标

v1.4 不包含：

- 自动联网抓取淘宝、Shopify、京东或其他平台实时政策。
- 客户上传附件、聊天图片识别或以客户文件作为共享政策来源。
- DOCX、XLSX、PPTX、HTML、音频、视频、网页爬取或任意文件格式插件。
- 自动生成、自动批准或自动发布政策；LLM/OCR 结果不能跳过管理员 Review。
- 完整文档管理、多人审批、电子签名、法律合规或真实企业知识治理平台。
- 根据政策图片、向量相似度或 LLM 结论直接授权退款。
- 新退款类型、退货、换货、维修、逆向物流、部分退款或真实交易接入。
- 知识图谱、多 Agent、Supervisor、开放式研究、模型微调或训练平台。
- 为向量能力迁移业务数据库到 PostgreSQL、拆分微服务、引入消息队列或多实例高可用。
- 补齐已延期的 Docker 参考环境 Gate。

## Eval 数据集

v1.4 至少新增 `56` 个固定合成场景：

| 类别 | 最少数量 |
|---|---:|
| 文件导入、版本、发布、重复与重建 | 8 |
| 条款编号、期限、金额等精确检索 | 8 |
| 口语、同义表达和查询改写 | 10 |
| 扫描页、图片、表格和定位引用 | 8 |
| 跨文档、多条件、订单绑定和澄清 | 10 |
| 版本、生效期、区域、冲突和证据不足 | 6 |
| Prompt Injection、越权、超限和陈旧索引 | 6 |
| 合计 | 56 |

Eval 必须同时保留：

- 现有 FTS5-only Baseline。
- v1.4 Hybrid Candidate。
- 数据集、政策来源、解析器、Embedding/检索配置、模型和代码版本指纹。
- 结果指标与工具/检索轨迹指标。
- Offline Gate 与真实 Provider Qualification 的独立结果。

## 验收条件

1. 管理员可以导入白名单政策文件，并看到稳定来源 ID、版本、Hash、适用范围和处理状态。
2. 游客和注册客户不能调用导入、发布、取代、重建或解析诊断接口。
3. 损坏、加密、伪造媒体类型、超限和重复文件均有确定性结果，不产生可发布的半成品来源。
4. Markdown/JSON、文本 PDF、扫描 PDF、PNG/JPEG 和含表格 PDF 各至少有一个固定成功样本。
5. 页面、章节、表格行列或图片区域定位可以从 Evidence Unit 解析回相同 Source Version。
6. OCR、表格和视觉解析的低置信或无法定位内容具有显式警告，不能直接支持关键结论。
7. 只有管理员显式确认且索引与 Source Version/Hash 一致的来源能够进入 `published`。
8. Source Version 发布后不可原地改写；新内容创建新版本，旧版本保留可追溯状态。
9. 全文精确检索继续工作，并新增独立、可重建的向量语义检索路径。
10. 混合检索在专门的口语/同义挑战集上 `Recall@5` 达到至少 `90%`，并严格优于相同数据的 FTS5-only Baseline。
11. 条款编号、期限、金额和商品条件精确子集的必要证据召回率保持 `100%`，不得因向量融合回退。
12. 全部固定场景的关键证据 Recall 不低于 `95%`；退款确定性规则所需的必要政策事实 Recall 为 `100%`。
13. 已发布状态、区域、生效时间和版本过滤正确率为 `100%`；使用过期、未发布或跨区域政策形成当前结论数量为 `0`。
14. 扫描页、图片和表格固定子集的必要证据 Recall 不低于 `90%`。
15. 所有面向用户的关键政策结论具有有效 `evidence_id`；引用解析、版本和内容 Hash 校验正确率为 `100%`。
16. 口语化、跨文档、多条件和订单绑定问题能够分解为有限子问题，并在固定预算内停止。
17. 缺少商品类别、拆封状态、签收时间等必要条件时提出最小澄清，不以相似候选替代用户事实。
18. 无证据问题不生成政策结论；无法消解的当前政策冲突展示双方引用。
19. 一线政策回答和 L2 Agent 只能使用当前 Evidence Pack 中的证据；未入包来源引用数量为 `0`。
20. L2 Observation、Context Pack、Checkpoint、公开消息和日志均不保存原始二进制、完整页面图片或向量。
21. 政策文件、OCR 内容、图片文字和用户问题中的 Prompt Injection 不能改变权限、过滤、工具或动作。
22. 检索结果、向量分数和 LLM 输出不能授权退款；未经批准或重复 Mock 退款数量为 `0`。
23. 向量索引不可用、陈旧、Hash 不匹配或重建中断时安全降级，不读取半成品索引或伪造成功。
24. 重复导入、解析重试、发布重试和索引重建保持幂等，不产生重复有效来源或重复证据。
25. 历史政策引用仍可说明原版本；新会话不会把已取代版本当作当前政策。
26. 管理员运营页面不展示完整客户问题、Prompt、密钥、向量或服务器绝对路径。
27. 固定 v1.4 Suite 至少 `56/56` 通过，安全违规、跨用户读取、未授权发布和真实外部副作用均为 `0`。
28. 既有 v0.1–v1.3 测试、Offline Eval、退款安全门禁和公开会话恢复保持通过。
29. README、目标地图、代码职责、来源管理、索引重建、已知限制和 Eval 报告与最终实现一致。
30. Tech Plan 必须在实现前明确向量数据库、Embedding/多模态模型、解析器、融合/Rerank、资源预算、迁移、备份和故障降级，并判断是否需要新增 ADR。
