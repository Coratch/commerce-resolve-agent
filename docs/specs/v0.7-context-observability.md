# Feature Spec：v0.7 L2 上下文工程、轨迹回放与可观测性

状态：Accepted  
日期：2026-07-21  
接受日期：2026-07-21  
依赖版本：v0.6 会话生命周期、历史恢复与可恢复交互

## 目标

受邀注册用户在长对话和多步骤 AI 二线客服 Case 中，仍能得到基于当前任务、最新业务事实、
有效政策和已确认偏好的回答；用户可以看到回答使用了哪些公开证据，并在刷新或重新登录后
按原顺序查看已经发生的处理轨迹。

开发与 Eval 可以进一步判断每一步选择了哪些上下文、为什么选择或排除、消耗了多少预算、
在哪里失败，而不保存或展示完整 Prompt、隐藏推理和敏感工具正文。

本版本解决的是“模型每一步看到了什么公开事实，以及为什么能够信任处理过程”，不是增加
新的业务能力。订单、物流、政策、退款、长期记忆和 L2 工具权限继续使用既有边界。

## 第一性原则

1. 模型输出质量上限由有效上下文决定；把所有历史全部传入不等于理解更多。
2. 上下文必须足够、相关、最新、可信、可追溯，而不是单纯追求更多 Token。
3. 当前业务 Repository 和有效政策优先于历史消息、旧 Observation、长期记忆和模型文本。
4. 长期记忆只表达用户确认的低风险偏好，不能成为订单、退款或政策事实。
5. 选择上下文和授权工具是两件事；任何检索结果都不能扩大权限或跳过审批。
6. 轨迹回放是读取既有记录，不是重新执行模型、工具、记忆写入或 Mock 退款。
7. 可观测性记录结构化事实和指标，不记录隐藏 Chain-of-thought。
8. 先证明确定性筛选和现有精确检索不足，再考虑 Embedding、向量数据库或 Rerank。
9. 不能通过固定场景评估的上下文策略，不进入长期产品路径。

## 当前基线与问题

v0.5–v0.6 已提供：

- 单个有界 L2 Agent、固定工具白名单、步骤/模型/工具/Token 预算和安全停止。
- 当前问题摘要、最近公开消息、已验证 Observation、已确认偏好和剩余预算。
- 订单、物流、退款、政策和偏好五类 R0 工具。
- L2 Case 公开状态、脱敏工具事件、模型计量、Checkpoint 和跨页面恢复。
- 公开会话消息、Run/Event SSE 与内部 LangGraph State 的物理和协议分离。

当前缺口：

- 上下文主要按固定数量打包，缺少统一的相关性、优先级、时效和冲突语义。
- 长对话中，当前任务所需的早期信息可能被固定消息窗口排除；直接扩大窗口又会增加噪声。
- Observation 可以恢复循环，但没有统一说明旧观察何时必须重新查询。
- 每次模型调用没有稳定的上下文清单，难以判断错误来自模型还是缺失、过期或冲突上下文。
- 公开 Trace 可以查看工具步骤，但不能以只读方式完整回放“准备上下文→决策→工具→停止”。
- 已有模型和工具计量尚未形成 Case 级结果、上下文和失败归因视图。

## 术语

| 术语 | 含义 |
|---|---|
| Context Candidate | 某一步可能需要的消息、业务事实、政策证据、Observation 或已确认偏好 |
| Context Pack | 经过身份、相关性、时效、优先级和预算筛选后实际交给模型的结构化上下文 |
| Context Manifest | 描述候选来源、选择结果、排除原因、版本、时效和预算的结构化清单 |
| Essential Context | 完成当前步骤不可缺少的目标、实体、事实、权限或证据 |
| Freshness | 上下文与当前业务/政策来源版本是否仍一致 |
| Conflict | 两个可信候选对同一事实给出不兼容值，且不能由优先级直接消解 |
| Public Trace | 当前用户可以查看的脱敏 Case 事件、证据、状态、耗时和停止原因 |
| Diagnostic Trace | 仅供本地开发与 Eval 使用的上下文清单、筛选原因、预算和失败分类 |
| Replay | 按已持久化顺序读取 Trace；不调用模型、工具或任何写操作 |
| Failure Attribution | 将失败稳定归类到上下文、模型、工具、Policy、预算、验证或用户输入 |

## 角色与可见范围

### 注册用户

- 只能查看本人工作区、本人 conversation 所关联的 L2 Case 公开轨迹。
- 可以看到使用的公开来源类型、可定位证据、处理阶段、结果、耗时和停止原因。
- 不能看到完整 Prompt、隐藏推理、原始工具正文、其他候选上下文或内部筛选分数。

### 游客

- 继续使用 v0.6 的确定性一线 Fake 模式，不能启动 L2 Case。
- 不新增 Context Manifest、L2 Trace 或真实模型调用权限。

### 本地开发与 Eval

- 可以在隔离测试数据中查看 Diagnostic Trace、上下文预算和失败归因。
- 诊断能力不构成公开 Web 管理后台，也不能绕过身份和数据最小化规则。
- 真实用户数据不能因为“调试模式”进入完整 Prompt、日志或 Eval 报告。

## 用户故事

### 长对话仍能继续当前任务

用户在同一 conversation 中经历多个订单和多个问题后，明确回到某个订单的退款问题。L2
Agent 能识别当前目标和相关订单，只选取必要的近期对话、最新业务事实和政策证据；无关的
寒暄与已结束任务不会挤占关键上下文。

### 业务事实变化后使用最新结果

用户早期查询时订单仍在运输，之后在订单页把演示物流更新为已签收。L2 Agent 下一次作出
与退款或政策有关的结论前重新读取必要事实，不让旧 Observation 覆盖最新 Repository 结果。

### 用户知道回答依据

L2 Agent 完成回答后，用户可以展开处理依据，看到使用了订单、物流、退款状态或政策等
公开来源及可定位引用，但不会看到系统 Prompt 或模型的隐藏思考过程。

### 刷新后回放处理过程

用户刷新页面或重新登录后，可以从第一条已公开 Case 事件开始按原顺序查看处理步骤。回放
不会产生新的模型计费、工具调用、Case、长期记忆或 Mock 退款。

### 开发者能够定位失败层级

固定场景失败时，开发者可以判断是必要上下文未入选、业务事实过期、来源冲突、模型输出
无效、工具失败、Policy 阻断、预算耗尽还是结果验证失败，而不依赖猜测完整 Prompt。

## 上下文来源与优先级

v0.7 允许 L2 Context Pack 使用以下来源：

| 优先级 | 来源 | 使用边界 |
|---:|---|---|
| 1 | 系统规则、工具契约、身份作用域和剩余预算 | 每次模型决策必须存在，不能被数据覆盖 |
| 2 | 当前 Case 目标、相关订单和 Pending Action | 保持任务连续性，不能从模型自由文本伪造 |
| 3 | 最新业务工具事实 | 必须来自当前用户/工作区授权的 Repository/Gateway |
| 4 | 当前有效政策证据 | 保留文档、版本、片段和事实标识 |
| 5 | 当前 Case 已验证 Observation | 使用前检查来源、参数、版本和时效 |
| 6 | 与当前任务相关的公开对话 | 只选择必要消息，不默认传输全部历史 |
| 7 | 用户确认的低风险长期偏好 | 只能影响语言、详细程度和沟通风格等允许字段 |

低优先级来源不能覆盖高优先级事实。用户文本、模型输出、政策正文、工具正文和长期记忆均
视为不可信数据，不能改变工具白名单、身份、预算、Policy 或审批结果。

## Context Pack 行为

每次 L2 模型调用前必须形成一个受限 Context Pack，并满足：

- 绑定稳定的 Case、Step、用户、工作区和上下文策略版本。
- 明确当前目标、相关业务实体、可用工具和剩余预算。
- Essential Context 优先于可选历史和表达偏好。
- 候选信息超过预算时按已定义优先级裁剪；不能静默裁掉身份、权限、当前目标和必要事实。
- 无法在预算内保留 Essential Context 时不调用模型，进入明确的补充信息或安全停止状态。
- 同一事实只保留当前可信版本；重复消息和重复 Observation 不重复占用上下文。
- Context Pack 具有有限大小，不保存完整业务库、完整 conversation 或不可重建的大型正文。
- 交给云模型的字段必须与服务端公开的模型数据范围一致，不因诊断能力额外发送本地数据。

上下文选择不能只由 LLM 自由决定。模型可以提出需要哪类事实，但候选来源、身份过滤、
优先级、时效、预算和最终可用字段必须由确定性代码约束。

## 长对话与任务连续性

- 当前 Case 目标、相关订单、未解决问题、Pending Action 和用户最新补充属于必要工作上下文。
- 最近消息窗口只能作为候选来源，不能成为唯一任务记忆。
- 早期消息仍与当前任务相关时，系统必须通过可定位引用保留或重新取得，而不是靠模型猜测。
- 已结束任务和无关闲聊默认不进入 Context Pack；排除不改变公开聊天历史。
- 任何摘要只用于导航和选择，不能替代最新订单、物流、退款或政策事实。
- 摘要必须能追溯到公开消息或已验证 Observation；无法追溯时不作为事实使用。
- 信息不足或指代存在歧义时向用户澄清，不跨订单、Case 或 conversation 猜测。

## 时效、冲突与失效

- 与订单、物流、支付、退款或 Pending Action 有关的最终结论必须使用当前授权来源的最新值。
- 历史 Observation 必须携带来源引用和取得时间；来源已变化或无法验证时标记为 stale。
- stale Observation 可以用于解释历史过程，不能作为当前业务结论的唯一依据。
- 政策必须保留版本、有效期和区域；失效版本不能覆盖当前有效政策。
- 当前业务事实与历史消息冲突时，以当前业务事实为准，并向用户说明状态已变化。
- 两个当前可信政策来源发生无法自动消解的冲突时，展示冲突或安全停止，不能静默选择。
- 发现上下文不完整、过期或冲突时，必须在调用模型前补取、澄清或停止。

## 长期记忆使用边界

- 只有用户已经确认且仍符合受限 Schema 的偏好可以成为 Context Candidate。
- 只选择与当前回复表达有关的偏好，不默认传入全部长期记忆。
- 长期记忆不能提供订单号、物流、退款资格、金额、政策结论、权限或审批结果。
- 已删除、作用域不匹配或 Schema 无效的记忆不能进入 Context Pack。
- 使用记忆必须在 Context Manifest 中留下类型和稳定引用，但公开 Trace 不展示不必要正文。
- v0.7 不改变记忆建议、确认、纠正和删除流程，也不自动从会话提取新记忆。

## Context Manifest

每次模型调用必须产生可验证的 Context Manifest，至少能回答：

- 这是哪个 Case、Step 和上下文策略版本。
- 候选来自哪些允许的来源类型。
- 哪些候选被选择、去重、裁剪、判定过期或因作用域拒绝。
- 每个选中项对应哪个公开消息、业务实体、政策证据、Observation 或记忆引用。
- Essential Context 是否齐全。
- 选择前后上下文大小、预算和是否发生截断。
- 是否发现冲突、需要重新查询或等待用户输入。

Context Manifest 是结构化诊断事实，不保存完整 Prompt、隐藏推理、密钥或完整敏感正文。
公开给用户的投影只包含来源类别、可公开引用、阶段和结果；候选排除细节仅用于本地测试与
诊断。

## 公开轨迹与只读回放

公开轨迹至少能够按 Case 顺序表达：

```text
Case 创建
→ 上下文准备完成或需要补充
→ 模型产生一种结构化决策
→ 工具候选通过或未通过 Harness
→ 工具返回经过验证的 Observation
→ 等待用户 / 等待审批 / 继续决策
→ 回答、失败、预算耗尽或安全停止
```

- 每条事件具有稳定标识、Case/Step、公开类型、状态、耗时和时间。
- 上下文事件只公开来源类别、选中数量、必要证据和截断状态，不公开完整内容。
- 工具事件继续只公开工具类别、脱敏参数、结果码和证据标识。
- 回放读取已持久化事件，不重新执行任何节点、模型、工具或写操作。
- 重复读取、刷新、分页或 SSE 重连不会新增事件或改变 Case 状态。
- 事件缺失、损坏或属于旧版本时显示 `partial` 或不可用，不从 Checkpoint 猜测补造。
- 用户只能回放本人有权访问的 Case；不存在和无权访问使用统一错误语义。

## 可观测指标

每个 L2 Case 和模型步骤至少提供以下可聚合指标：

- Case 总步骤、模型调用、工具调用、补充信息、审批和重试次数。
- Context Candidate、选中、去重、过期、冲突和裁剪数量。
- Context Pack 的确定性大小估算，以及 Provider 返回时的输入/输出 Token。
- 模型、工具、上下文准备和 Case 总耗时。
- 预算上限、已使用量和停止时剩余量。
- 最终状态、停止原因、失败归因和是否需要用户操作。

Provider 没有返回 Token usage 时只能明确标记为估算；没有配置价格时不能伪造金额成本。
公开用户界面只展示理解 Case 所需的有限指标，完整聚合用于本地 CLI/Eval。

## 失败归因

v0.7 至少区分：

| 类别 | 含义 |
|---|---|
| `context_missing` | Essential Context 缺失，且无法安全补取 |
| `context_stale` | 必要事实已经过期或无法验证 |
| `context_conflict` | 当前可信来源发生无法消解的冲突 |
| `user_input_required` | 必须等待用户补充或澄清 |
| `model_unavailable` | Provider 不可用或超时 |
| `model_output_invalid` | 模型输出不能通过结构化 Schema |
| `tool_rejected` | 工具或参数未通过白名单、身份或 Policy |
| `tool_failed` | 合法工具调用返回技术或业务失败 |
| `policy_blocked` | 动作不满足确定性业务或审批条件 |
| `budget_exhausted` | 步骤、模型、工具、Token 或时间预算耗尽 |
| `verification_failed` | 执行结果无法由真实业务状态验证 |

失败归因是结构化诊断结论，不由模型自由编写。用户只看到稳定、可行动且不泄露内部细节的
公开说明；开发与 Eval 可以查看对应的脱敏步骤和上下文证据。

## 范围

包含：

- 单个 L2 Agent 每一步的统一 Context Candidate、Context Pack 和 Context Manifest 语义。
- 当前任务、公开消息、最新业务事实、政策、Observation 和已确认偏好的受控选择。
- 长对话中的目标连续性、去重、预算裁剪、时效检查和冲突处理。
- 本人 L2 Case 的公开证据摘要、处理轨迹和只读回放。
- 本地开发/Eval 使用的脱敏诊断轨迹、Case/Step 指标和失败归因。
- 旧 Case 的 partial/unavailable 兼容语义。
- Fake Model、Fake Tool、临时数据库和固定 Context/Trace Eval。
- v0.1–v0.6 自动化测试、固定 Eval、OpenAPI 和浏览器路径完整回归。

## 非目标

- 新订单、物流、政策、退款、记忆或外部业务工具。
- 多 Agent、Supervisor、专家路由、Agent 间通信或后台自治。
- 自动执行历史轨迹、重新调用模型/工具或重新产生退款和记忆副作用。
- 保存、展示或导出完整 Prompt、隐藏 Chain-of-thought、模型草稿或原始 ToolMessage。
- 对 v0.2 政策 RAG 无证据增加 Embedding、向量数据库、Rerank 或知识图谱。
- 自动总结所有会话并写入长期记忆、自动用户画像或跨用户记忆。
- Provider Token 级 SSE、消息重新生成、分支或编辑。
- 接入 LangSmith、Langfuse、OpenTelemetry、外部 APM 或云端 Trace 服务。
- 生产级日志平台、计费系统、SLA、多实例 Trace 汇聚或无限保留。
- 真实电商、客服、支付、物流、CRM 或外部副作用。

## 公开错误与降级语义

- Essential Context 缺失时优先请求用户补充；无法补充则安全停止，不让模型猜测。
- 最新业务事实不可用时明确说明暂时无法验证，不复用旧结果冒充当前状态。
- Context Manifest 无法生成或校验时不调用模型，并保存稳定失败归因。
- 公开 Trace 暂时不可用不应改变 Case 业务状态；页面显示可重试的只读错误。
- 旧 Case 没有完整 Context Manifest 时标记 `partial`，仍可查看已有 v0.5 公开 Trace。
- Provider Token 或费用信息不可得时显示“未提供”或“估算”，不能填充虚假数值。
- 诊断记录失败不能绕过工具、Policy、审批或结果验证，也不能把业务成功伪装为诊断成功。

## 身份、安全与数据最小化

- Context Candidate 在读取正文前先校验当前 Principal、工作区、conversation、Case 和实体归属。
- 不同用户、工作区、游客 Session 和 Case 的消息、业务事实、记忆、Manifest 和 Trace 不得混用。
- Context Manifest 使用稳定引用、类型、版本、摘要和计数，不复制完整订单、支付或工具正文。
- Prompt Injection 只能作为数据被记录或拒绝，不能修改候选来源、选择规则、工具或预算。
- 完整 Prompt、隐藏推理、API Key、Cookie、CSRF Token、密码、邀请码和支付凭据不得进入
  Manifest、Trace、浏览器、日志或 Eval 报告。
- 用户删除公开 conversation 后，消息、Checkpoint、L2 Case/Audit、长期记忆和诊断数据继续
  遵守各自既有的独立删除与保留语义；v0.7 不静默扩大级联删除。
- Web Replay 和指标读取继续执行当前 Session、Origin 和归属校验；任何未来写请求仍需 CSRF。
- 本地诊断只面向显式启动的开发/Eval 流程，不能成为绕过 Web 授权读取真实用户数据的入口。

## 与已有版本的兼容要求

- v0.1 订单/物流查询、跨进程 Checkpoint 和固定 Eval 保持不变。
- v0.2 政策检索、冲突、拒答和引用语义不降低。
- v0.3 游客零 LLM、注册身份、私有工作区和模型授权不改变。
- v0.4 退款资格、金额、审批、幂等执行和回读验证不改变。
- v0.5 单 Agent、工具白名单、预算、长期记忆确认和公开 Trace 权限不放宽。
- v0.6 公开消息、Run/Event SSE、会话生命周期、显式重试和删除语义不改变。
- 简单一线请求不会为了生成 Context Manifest 被强制升级为 L2。
- v0.7 之前完成的 L2 Case 可以显示已有公开 Trace，但不伪造历史 Context Manifest。
- 数据或 State 变更必须增量迁移，不能要求删除现有本地业务库、Checkpoint 或 Memory Store。

## 验收条件

1. 每次 L2 模型调用都绑定一个通过严格 Schema 的 Context Pack 和 Context Manifest。
2. Manifest 可以确定性说明选中、去重、裁剪、过期、冲突和作用域拒绝的候选数量及原因。
3. 当前目标、相关实体、权限、工具白名单和预算不会因长对话裁剪而丢失。
4. 至少 30 条公开消息的固定长对话中，Agent 仍能定位当前任务和正确订单，不混入已结束任务。
5. 无关消息和重复 Observation 不进入模型上下文，且不从公开历史中删除。
6. Essential Context 超出或无法满足预算时不调用模型，进入补充信息或安全停止状态。
7. 订单、物流、支付或退款变化后，旧 Observation 不会成为当前结论的唯一依据。
8. 当前业务事实与历史消息冲突时使用最新业务事实，并提供状态变化说明。
9. 当前有效政策发生冲突时展示冲突或停止，不静默选取任一来源。
10. 只有当前用户确认、作用域匹配且 Schema 有效的低风险偏好可以进入 Context Pack。
11. 长期记忆不会覆盖业务事实、政策、权限、风险或审批结果。
12. 用户、政策、工具结果和记忆中的 Prompt Injection 不能改变上下文规则或触发越权工具。
13. 不同用户、工作区、conversation 和 Case 的上下文及轨迹泄露数量为 `0`。
14. 用户可以刷新、重新登录并从同一 Case 起点按原顺序读取全部可用公开轨迹。
15. Replay 不产生新的模型调用、工具调用、Case、消息、长期记忆、退款或审计成功事件。
16. 重复 Replay、分页和 SSE 重连不会重复持久事件或改变 Case 终态。
17. 旧 Case 缺少 v0.7 诊断字段时显示 `partial` 或不可用，不从 Checkpoint 猜测补造。
18. 每个 Case 可以查询步骤、模型/工具次数、上下文计数、Token、耗时、预算和停止原因。
19. Provider usage 缺失时指标明确标记估算；未配置价格时不显示虚假金额成本。
20. 固定失败场景可以稳定归因到上下文、用户输入、模型、工具、Policy、预算或验证层。
21. 公开响应不包含完整 Prompt、隐藏推理、原始工具正文、内部筛选分数、密钥或其他用户数据。
22. 自动化测试使用 Fake Model、Fake Tool 和临时存储，不依赖真实网络或 API Key。
23. v0.1–v0.6 自动化测试、固定 Eval、OpenAPI 类型和浏览器路径全部继续通过。

## v0.7 Eval

固定数据集建议包含 `36` 个场景：

| 类别 | 数量 | 核心覆盖 |
|---|---:|---|
| 上下文选择与相关性 | 8 | Essential Context、去重、裁剪、无关历史和来源引用 |
| 长对话与任务连续性 | 6 | 30+ 消息、多订单、旧信息回取、澄清和 Pending Action |
| 时效与冲突 | 6 | 订单/物流变化、stale Observation、政策版本和冲突停止 |
| 记忆、隔离与注入 | 6 | 已确认偏好、删除/越权记忆、跨用户和四类 Prompt Injection |
| 轨迹与回放 | 5 | 顺序、分页、刷新、partial 兼容和零副作用 Replay |
| 可观测性与失败归因 | 5 | 指标、usage 估算和上下文/模型/工具/预算/验证归因 |

发布门槛：

- 固定场景通过率：`100%`。
- Essential Context 召回率：`100%`。
- 固定场景中的无关或禁止上下文入选数量：`0`。
- 超过 Context、步骤、模型、工具、Token 或时间预算的调用数量：`0`。
- 使用 stale 业务事实作当前结论的数量：`0`。
- 跨用户、跨工作区、跨 Case 上下文和 Trace 泄露数量：`0`。
- Prompt Injection 导致规则、工具、权限或审批变化数量：`0`。
- Replay 产生的新模型/工具调用或业务副作用数量：`0`。
- 固定失败场景归因正确率：`100%`。
- 公开 Trace 泄露 Prompt、隐藏推理、原始工具正文或密钥数量：`0`。
- 指定长上下文场景相对未筛选候选集合减少至少 `30%` 的确定性输入大小，任务正确率不降低。
- v0.1–v0.6 测试和固定 Eval：全部通过。

确定性断言覆盖 Context Manifest、来源引用、Context Pack、预算、Trace、Case State、工具轨迹、
业务结果和副作用。自然语言措辞不要求逐字一致；LLM-as-judge 只能作为补充，不能单独决定
发布。

## 已知限制

- v0.7 只优化 AI 二线客服上下文，不重写一线订单/物流查询和政策 RAG。
- Context Pack 的确定性 Token 估算不等于所有 Provider 的真实分词结果。
- Public Trace 是脱敏事件，不是完整模型执行转储或法律审计系统。
- Replay 只读，不支持从历史步骤分支、修改上下文或重新执行。
- 旧 L2 Case 不保证具有完整 Context Manifest 和新指标。
- SQLite、单实例和进程内后台任务不代表生产级 Trace 汇聚、高可用或无限保留。
- 所有业务和资金结果继续来自本地 Mock/Fake 系统。

## 已接受决策与下一步

本 Spec 已接受：

1. v0.7 只扩展现有单个 L2 Agent，不新增 Agent 或业务工具。
2. Context Pack 由确定性规则筛选，模型不能自行扩大来源和权限。
3. 业务事实在需要作当前结论时重新验证，历史 Observation 不能静默覆盖最新数据。
4. Replay 只读取已记录事件，永不重新执行模型、工具或副作用。
5. Public Trace 与 Diagnostic Trace 分离，二者都不保存隐藏推理和完整 Prompt。
6. 先使用现有精确来源和确定性选择，不引入向量数据库或外部可观测平台。
7. 固定 v0.7 Eval 使用 36 个场景并执行上述发布门槛。
