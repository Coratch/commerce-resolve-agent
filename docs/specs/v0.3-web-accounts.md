# Feature Spec：v0.3 Web、邀请注册与私有业务数据

状态：Accepted  
实施状态：Completed  
日期：2026-07-17  
接受日期：2026-07-17  
完成日期：2026-07-17  
依赖版本：v0.2 售后政策 RAG 与可定位来源

## 目标

用户可以通过浏览器与 CommerceResolve 对话。未登录游客使用共享的只读演示订单、
物流数据和确定性 Fake 模式；持有效邀请码注册并登录的用户获得私有演示工作区，
可以维护自定义订单与物流数据，并使用服务端授权的 LLM 模式查询这些数据和售后政策。

本版本建立“Web 交互 → 服务端身份 → 工作区数据隔离 → 模型权限 → 既有
LangGraph 能力”的最小产品闭环。它不执行退款，也不把自定义演示数据描述为真实
电商平台数据。

## 第一性原则

1. 游客体验不能产生不可控的模型成本或业务写入。
2. 身份、数据归属和 LLM 使用权是三种独立权限，必须由服务端确定。
3. 客户端提交的 `user_id`、`workspace_id` 和模型模式都是不可信输入。
4. 注册用户之间的数据和会话必须隔离；订单号本身不能作为授权依据。
5. Web 数据管理是确定性演示后台，不通过 LLM 修改订单或物流。
6. LLM 只理解问题；订单、物流和政策结论仍来自受控数据源。
7. 模型不可用时应明确失败，不能静默切换 Fake 并伪装为相同能力。
8. 先建立身份与数据边界，再在后续版本开放退款等高风险动作。

## 角色与访问模式

| 角色 | 身份 | 数据范围 | 对话解释器 | 数据写入 |
|---|---|---|---|---|
| 游客 | 匿名浏览器会话 | 共享演示工作区 | Fake | 禁止 |
| 受邀用户 | 已登录账号 | 所属私有演示工作区 | 服务端授权的 LLM | 仅管理本工作区订单与物流 |
| 可信操作员 | 本地或受保护管理入口 | 邀请记录 | 不适用 | 签发和失效邀请码 |

“受邀用户维护订单与物流”是项目提供的私有演示数据工作台。真实电商客户通常无权
直接修改平台订单或物流，本版本不声称复刻该生产权限模型。

## 用户故事

### 游客体验对话

作为游客，我无需注册即可进入 Web 对话页面，查询预置订单、物流和售后政策，了解
产品能力；系统不调用真实 LLM，也不允许我修改共享演示数据。

### 使用邀请码注册

作为收到邀请码的用户，我可以创建账号并登录。无效、过期、已失效或已达到使用上限
的邀请码不能创建账号，也不能作为后续登录凭证。

### 管理私有演示数据

作为已登录用户，我可以在独立的数据管理页面创建、查看、修改和删除自己的演示订单
与物流记录。所有关系和状态必须通过确定性校验，不能写入其他工作区。

### 使用 LLM 查询自定义数据

作为已登录用户，我可以用自然语言查询刚刚维护的订单和物流；系统使用 LLM 提取结构化
诉求，但最终回答只依据我所属工作区的业务数据。

### 继续既有会话

作为已登录用户，我可以在服务重启后继续同一个 `thread_id`。恢复后的任务仍绑定原账号
和工作区，不能通过修改请求参数切换身份或数据范围。

## 范围

包含：

- 浏览器中的游客和注册用户对话页面。
- 游客匿名会话、共享只读演示订单与物流数据，以及 Fake Interpreter。
- 邀请码签发、失效、注册消费、登录和退出的最小闭环。
- 注册用户私有演示工作区及订单、物流的创建、查看、修改和删除。
- 服务端根据可信身份装配业务 Repository、Interpreter 和 LangGraph Runtime Context。
- 注册用户使用 LLM 查询私有订单、物流和 v0.2 受控政策。
- 注册会话与 LangGraph 会话跨服务重启恢复。
- 模型未配置、调用失败、配额不足和访问被禁用时的明确错误。
- 既有 CLI、v0.1 订单查询、v0.2 政策 RAG、测试和 Eval 的完整回归。
- 固定的 v0.3 身份、隔离、模型授权和 Web 行为 Eval。

本版本只覆盖单实例、本地演示部署和一个受控政策区域。受邀账号默认只有一个私有
工作区，不在本版本提供组织、团队或多工作区管理。

## 非目标

- 退款预览、退款执行、订单取消、退货、换货或其他 Agent 业务写操作。
- 真实支付、真实物流或第三方电商平台接入。
- 公开注册、邮件验证、找回密码、OAuth、SSO 或多因素认证。
- 完整运营后台、角色权限矩阵、组织和租户计费。
- 通过自然语言创建或修改订单、物流；数据维护只走确定性 Web 管理能力。
- 人工客服 Handoff、动态 Agent Loop、多 Agent 或后台自治任务。
- WebSocket、复杂前端状态框架、移动端或公开第三方 API。
- 将 LLM API Key、邀请码或认证凭证下发到浏览器。

## 游客行为

- 每个浏览器游客会话获得服务端生成的匿名标识和独立对话 thread，不能共享一个全局
  `user_id` 或 `thread_id`。
- 游客只能读取明确标记为演示的数据；管理页面和数据写请求必须拒绝游客。
- 游客请求不得触发 LLM 调用，即使请求中伪造 Interpreter、账号、工作区或权限字段。
- 游客可以使用 v0.2 政策问答，但其问题解释由确定性 Fake 能力完成。
- 游客会话不提供账号级跨设备恢复承诺；会话丢失时不能访问其他游客的历史。

## 邀请、账号与登录行为

- 邀请码由可信操作员通过受保护入口签发，可配置失效时间和使用上限，且可以主动失效。
- 服务端不保存可直接用于注册的明文邀请码；日志和错误不得回显完整邀请码。
- 邀请码成功消费和账号创建必须是一个一致操作，重复提交不能创建多个账号或超额消费。
- 注册完成后邀请码不再充当认证凭证；用户必须通过账号认证建立服务端可信会话。
- 登录失败使用不泄露账号是否存在的统一错误语义。
- 退出或会话失效后，受保护页面、私有数据和 LLM 模式必须立即不可访问。
- 浏览器不能通过修改 Cookie 之外的普通业务字段伪造身份；具体会话和凭证方案由
  Technical Plan 确定。

## 私有订单与物流数据

- 注册用户只能看到和管理所属工作区的数据。
- 订单标识至少在工作区内唯一；物流记录必须引用同一工作区内存在的订单。
- 创建和修改必须通过 Schema 与确定性业务校验；无效状态或跨工作区关系不能写入。
- 删除或修改数据后，后续 Agent 查询必须读取最新业务状态，而不是复用 Checkpoint 中
  的旧订单或物流正文。
- 删除数据不会改写历史对话，但后续查询必须明确当前记录不存在。
- 订单、物流、账号和邀请属于业务事实，不能存入 LangGraph Checkpoint。
- 当前 Fake Gateway 继续服务游客与离线测试；注册用户在线路径必须使用私有业务
  Repository，不能把 Fake 数据混入私有工作区结果。

## 对话与模型权限

- Web 层从可信认证上下文生成 `user_id`、`workspace_id` 和访问模式，再调用同一核心 Graph。
- LangGraph State 可以保存稳定身份引用，但不能保存认证凭证、模型客户端或 LLM API Key。
- 游客固定使用 Fake Interpreter；注册用户只有在服务端授权、模型配置和用量限制均满足时
  才能进入 LLM 路径。
- 是否调用 LLM 不能由请求中的 `interpreter=openai` 或等价字段决定。
- 注册用户的 LLM 只输出现有 Schema 允许的 `Interpretation` / `PolicyQuery`，不能绕过
  Repository、订单归属验证或政策证据规则。
- 模型失败时不回退到 Fake；对外返回可重试且不暴露供应商密钥或内部 Prompt 的错误。
- 当前 CLI 的显式 Interpreter 选择只属于可信本地开发入口，不构成 Web 授权机制。

## Web 安全与错误语义

- 所有状态变更请求必须验证认证状态和请求来源，防止跨站请求伪造与重复提交。
- 账号凭证使用适合身份认证的单向算法保存；不能记录明文密码。
- API Key、完整邀请码、认证凭证、Cookie 和敏感个人信息不能进入 Prompt、Checkpoint 或日志。
- 不存在和无权限访问的私有订单继续使用统一错误语义，避免资源枚举。
- 模型、数据库或 Checkpointer 暂时失败时，不能返回伪造的订单、物流或政策结果。
- Web 错误不暴露本地路径、堆栈、数据库结构、Prompt 或依赖配置。
- 模型调用需要可计量、可限流和可停用；具体默认额度由 Technical Plan 确定。

## 公开用户结果

Web 至少区分：

- 游客演示对话成功。
- 邀请注册成功或邀请码不可用。
- 登录成功、认证失败或会话失效。
- 私有业务数据创建、更新、删除成功或校验失败。
- 订单/物流查询成功、资源不可访问或信息不足。
- 政策回答、澄清、无证据和冲突等 v0.2 状态。
- LLM 未授权、配额不可用或暂时失败。

具体 HTTP 状态码、页面路由、响应 Schema 和内部节点名称由 Technical Plan 定义。

## 与已有版本的兼容要求

- v0.1 的 15 个固定 Eval 场景必须继续全部通过。
- v0.2 的 20 个固定 Eval 场景必须继续全部通过。
- CLI 继续用于本地调试、索引构建和 Eval，不要求在本版本删除或替换。
- 政策语料、政策索引、Checkpoint、认证数据和业务数据必须保持独立。
- Web 不得通过复制一套 Graph 改变订单归属、政策引用或安全失败语义。
- State 或 Checkpoint 格式发生不兼容变化时，Technical Plan 必须给出迁移或开发期重建策略。

## 验收条件

1. 游客无需登录即可完成预置订单、物流和政策问答，LLM 调用次数为 `0`。
2. 游客创建、修改或删除订单与物流的请求全部被拒绝且没有副作用。
3. 有效邀请码可以创建一个账号；无效、过期、已失效或超过使用上限的邀请码不能注册。
4. 邀请码重复提交不会重复创建账号或超额消费。
5. 登录、退出和会话失效行为可重复验证；认证失败不泄露账号是否存在。
6. 注册用户可以创建、查看、修改和删除所属工作区的演示订单与物流。
7. 用户 A 无法读取或修改用户 B 的账号、会话、订单、物流和 Checkpoint。
8. 注册用户通过 LLM 查询自定义订单时，回答来自最新私有业务数据并执行订单归属校验。
9. 客户端伪造 `user_id`、`workspace_id`、Interpreter 或模型权限不能改变服务端选择。
10. 未授权、未配置、配额不足或失败的 LLM 请求不会静默降级为 Fake。
11. 注册用户复用同一 thread 时可以跨服务重启继续会话，且身份与工作区绑定不变。
12. 私有数据变化后 Agent 重新读取业务 Repository，不从 Checkpoint 返回过期业务事实。
13. LLM API Key、完整邀请码和认证凭证不出现在浏览器响应、Checkpoint 或应用日志中。
14. 自动化测试在没有网络和真实 API Key 时可以完整运行，并使用 Fake 依赖验证所有权限路径。
15. v0.1、v0.2 的自动化测试和固定 Eval 全部继续通过。
16. 一个真实 LLM 只用于受邀账号独立手工冒烟，不作为确定性发布门槛。

## v0.3 Eval

固定场景至少覆盖：

- 游客对话、只读和零 LLM 调用。
- 邀请码有效、无效、过期、失效、重复消费和使用上限。
- 登录、退出、会话失效和认证失败。
- 私有订单与物流的正常管理、无效关系和跨用户越权。
- 注册用户 LLM 查询、客户端模型伪造、模型不可用和配额拒绝。
- 同 thread 跨实例恢复和业务数据变化后的重新读取。
- v0.1 订单工具与 v0.2 政策 RAG 回归。

发布门槛：

- 固定场景通过率：`100%`。
- 游客触发 LLM 调用数量：`0`。
- 未授权业务数据读写数量：`0`。
- 客户端伪造身份、工作区或模型权限成功数量：`0`。
- 邀请重复消费导致的额外账号数量：`0`。
- 跨用户会话或 Checkpoint 泄露数量：`0`。
- 浏览器、Checkpoint 和日志中的密钥或明文凭证数量：`0`。
- v0.1、v0.2 回归：全部通过。

## 已知限制

- 账号、订单和物流都是本地演示系统数据，不接入真实电商平台。
- 单实例本地范围不代表生产并发、可用性和灾难恢复能力。
- 邀请注册不是完整的企业身份系统，不包含找回密码、OAuth 或多因素认证。
- 游客 Fake 模式只能覆盖预定义意图和样例表达，能力不等同于 LLM。
- v0.3 不支持退款、人工客服转接或 Agent 自主修改业务数据。
