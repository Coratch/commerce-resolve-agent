# Feature Spec：v0.1 订单与物流查询

状态：Accepted  
日期：2026-07-15

## 目标

用户通过对话查询属于自己的订单和物流状态。信息不足时，系统能够在同一会话中请求并接收订单号；程序退出后重新启动，仍可继续该会话。

本版本建立只读业务工具、会话隔离和持久化 State 的最小闭环，不处理退款或其他写操作。

## 用户故事

### 查询订单和物流

作为已知演示用户，我提供属于自己的订单号后，希望获得：

- 订单号与当前订单状态。
- 当前物流状态和最近一次物流事件。
- 预计送达时间；不存在时明确说明未知。

### 补充订单号

作为用户，我只说“帮我查一下物流”时，系统应询问订单号，并在我下一轮补充后继续原任务，而不是开始无关的新任务。

### 安全处理无权限订单

作为用户，当我查询不存在或不属于自己的订单时，系统不应泄露订单详情或订单是否属于其他用户。

### 恢复会话

作为用户，我在系统请求订单号后退出程序，再使用相同 `thread_id` 启动时，能够继续补充订单号并完成查询。

## 范围

包含：

- CLI 中创建和继续订单查询会话。
- 稳定的 `user_id`、`thread_id` 和订单标识。
- 只读订单查询与物流查询工具。
- 信息缺失、订单不可访问和工具暂时失败的处理。
- SQLite 持久化 Checkpoint。
- Fake Model、Fake Order/Logistics Adapter 和固定 Eval 场景。
- 一个真实模型的手工冒烟路径；自动化测试不依赖真实模型。

不包含：

- 退款申请、取消订单、修改地址或任何业务写入。
- 售后政策 RAG。
- 人工客服工单和 Handoff。
- 动态多工具 Agent Loop 或多 Agent。
- Web UI、公开 API、真实登录和多租户部署。
- Java/Spring Boot 业务服务。

## 业务规则

1. 查询必须同时携带 `user_id` 和 `order_id`，业务适配器负责校验归属。
2. 不存在和无权限访问的订单返回统一的 `order_unavailable` 结果。
3. 缺少订单号时不得调用订单或物流工具。
4. 工具结果是订单和物流事实来源，模型不得改写状态字段的含义。
5. 工具失败时返回暂时不可用，不把异常堆栈或内部连接信息暴露给用户。
6. v0.1 的所有业务工具均为只读，任何写操作请求都明确说明当前不支持。

## 对话行为

### 完整请求

```text
用户：查询订单 ORD-001 的物流
系统：查询订单归属和状态
系统：查询物流
系统：返回订单状态、物流状态、最近事件和预计送达时间
```

### 缺少订单号

```text
用户：帮我查一下物流
系统：请提供订单号
用户：ORD-001
系统：继续原查询并返回结果
```

### 订单不可访问

```text
用户：查询 ORD-999
系统：无法查询该订单，请检查订单号或当前账号
```

## 状态结果

任务至少区分以下公开状态：

- `awaiting_order_id`：等待用户补充订单号。
- `completed`：订单与物流查询成功。
- `order_unavailable`：订单不存在或无权访问。
- `temporarily_failed`：业务工具暂时失败，可稍后重试。
- `unsupported`：用户请求了 v0.1 不支持的写操作。

具体 State Schema 和节点名称由后续 Plan 定义。

## 验收条件

1. 已知用户查询自己的有效订单时，结果与 Fake 业务数据完全一致。
2. 缺少订单号时，系统进入 `awaiting_order_id`，且订单、物流工具调用次数均为 `0`。
3. 同一 thread 补充订单号后完成原查询，不要求重复描述诉求。
4. 程序退出并重新创建 Graph 后，相同 `thread_id` 可以从 SQLite 恢复等待状态。
5. 不同 `thread_id` 的会话状态互不影响。
6. 不同 `user_id` 查询同一订单时，未授权用户得不到任何订单或物流字段。
7. 不存在和未授权订单使用相同的公开错误语义。
8. 订单或物流工具失败时进入 `temporarily_failed`，不输出异常堆栈。
9. 取消、退款、修改地址等请求不会触发任何业务写操作。
10. 自动化测试全部使用 Fake Model 和 Fake Adapter，断网环境可以运行。

## v0.1 Eval

首个固定数据集至少包含：

- 4 个有效订单与物流查询。
- 3 个缺少或分两轮补充订单号的场景。
- 2 个不存在订单场景。
- 2 个越权订单场景。
- 2 个工具失败场景。
- 2 个不支持的写操作场景。

发布门槛：

- 工具选择与参数正确率：`100%`。
- 有效订单结构化结果正确率：`100%`。
- 越权数据泄露数量：`0`。
- 业务写工具调用数量：`0`。
- 会话隔离与跨进程恢复测试：全部通过。

模型自然语言措辞不要求逐字一致。

## 已知限制

- 用户身份和订单数据均为演示实现，不代表生产认证与真实电商系统。
- SQLite 仅用于本地单机学习，不代表生产部署方案。
- 本版本不回答售后政策，也不执行任何售后动作。
