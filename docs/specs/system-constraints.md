# Spec：系统约束

状态：Accepted  
日期：2026-07-15  
更新日期：2026-07-24

本文件适用于所有版本。Feature Spec 可以收紧这些规则，但不能绕过或静默放宽；需要改变时必须先更新本文件，并在符合条件时新增 ADR。

## 产品与责任边界

- 客户侧产品是订单优先的智能售后中心，通过 Web 处理订单与物流查询、政策问答、退款申请、公开会话和 AI 深度处理；CLI 保留为开发、管理和 Eval 入口。
- Web 产品分为客户售后中心与 Agent 运营控制台两个明确表面。客户售后中心只承载客户结果和本人可执行动作；运营控制台承载邀请、演示空间与版本、脱敏 Agent 监控、Eval、政策和受控维护能力。
- 两个产品表面继续复用同一个 React/Vite 前端工程、同源 FastAPI 模块化单体、领域服务和权威存储。界面与 API 命名空间分离不等于拆分后端服务、数据库事实或权限链路。
- 运营控制台的存在不能成为授权依据。所有后台读取和写入必须由服务端验证身份与权限；隐藏菜单、前端路由守卫或不可猜测 URL 均不能代替服务端授权。
- 订单、物流和售后服务记录是客户侧一级业务对象；对话是绑定当前用户、订单或服务目标的上下文能力，不能成为授权来源或唯一业务状态载体。
- Web 公开会话属于可恢复的产品对象；页面刷新、路由切换和重新登录不能依赖浏览器组件
  内存维持历史。
- 客户默认界面展示权威业务事实、服务进度、待办动作、政策依据和公开解释；LLM/Fake/Provider、Prompt、内部节点、Context Manifest、Token 和 Eval 指标不得成为正常客户界面的主要内容。
- 客户界面隐藏内部诊断不等于删除审计。公开证据可以渐进披露，受控 Trace、诊断和 Eval 继续按既有权限与生命周期保存；未来运营控制台也不能绕过身份、Policy 或审批。
- 运营控制台不得公开 API Key、Cookie、完整 Prompt、模型隐藏推理、未脱敏工具输出或跨用户正文；客户侧与运营侧使用同一套脱敏、审计和最小权限规则。
- 未登录访问者只能访问产品说明、登录和邀请注册入口，不能读取业务数据、创建会话、调用
  LLM/Fake Interpreter 或执行业务工具。
- 受邀注册用户使用私有演示工作区和真实 LLM。注册时由服务端自动初始化版本化 Mock
  数据；基准商品、订单、物流和退款前支付事实不能由客户或管理员在 Web 中逐项修改。
- 管理员只能重置完整演示工作区，不能任意创建、修改或删除单笔基准业务事实。退款、服务记录
  和 Mock Case 等派生事实只能通过对应的受控业务流程产生。
- 演示数据不得冒充真实电商平台数据。
- 订单、物流、支付、退款和 L2 Support Case 全部使用项目内 Mock/Fake 数据与适配器，不连接真实电商平台、客服、支付渠道、物流服务或交易系统，也不产生真实外部副作用。
- Mock 表示数据与外部真实系统隔离，不表示数据只能保存在内存。Web 路径可以把 Mock 业务状态持久化到本地业务数据库；离线测试可以使用内存 Fake 或临时数据库。
- 真实 LLM 可以用于注册用户的结构化意图理解、售后回复和受控 L2 Agent Loop，但不能
  改变所有业务数据和副作用均为 Mock 的边界。
- LangGraph 负责任务 State、路由、持久化、暂停恢复和 Agent Loop 编排。
- Mock 订单、物流、退款和 L2 Case 能力通过独立业务适配器提供；LangGraph 不是业务事实数据库。
- 售后服务进度如果由 Refund、Pending Action、L2 Case 或公开事件投影生成，该投影必须可追溯、可降级且不能取代原始权威事实。
- LLM 负责理解诉求、提取结构化信息、选择候选工具和生成用户回复。
- 结构化意图为 `unknown` 时必须进入有限澄清或安全兜底；澄清状态不能授权业务工具，
  次数由服务端持久化 State 控制，不能依赖 Prompt 或前端计数。
- LLM 不能决定退款资格、计算最终金额、授权退款、伪造业务结果或绕过人工审批。
- AI 深度处理必须明确披露为 AI，不能冒充真人客服或获得独立授权身份。

## 事实与信任模型

事实优先级为：

```text
项目内 Mock 业务 Repository/Gateway 返回值
→ 已发布且带版本的售后 Policy
→ 当前任务中经过验证的 State
→ 模型生成内容
```

- 模型输出、用户输入、知识文档和工具错误均视为不可信输入。
- 模型输出进入路由、工具或持久化 State 前必须通过 Schema 校验。
- 面向用户的订单、物流和退款结论必须来自项目内 Mock 业务工具结果。
- 无法验证业务状态时明确失败或建议进入受控 AI 深度处理，不用模型推测补全。

## 身份与数据隔离

- 每次任务必须关联稳定的 `user_id` 和 `thread_id`。
- Web 请求中的可信身份、工作区和模型权限必须来自服务端认证上下文，不能接受客户端直接指定或覆盖。
- 未登录访问者、注册用户和不同私有工作区的业务数据、公开消息、会话、Checkpoint 与审计记录必须隔离。
- 未登录访问者不能读取共享演示数据；产品不再提供共享游客工作区。
- 受邀注册用户只能查询所属私有工作区中的 Mock 订单、物流以及退款前所需的最小支付事实。
- 注册时初始化的基准事实和受控流程产生的派生事实必须分离；客户请求、LLM、管理员页面或退款
  审批请求均不能直接把业务记录改写为目标状态。
- 查询订单前必须验证订单归属；不能只凭订单号返回信息。
- 不存在和无权限访问的订单使用不泄露资源存在性的统一错误语义。
- 不同用户和 thread 的 State、Checkpoint、审计记录不得相互读取。
- v0.1 可以使用固定演示身份和 Fake 数据，但不能把该方案描述为真实身份认证。

## Web、邀请与模型权限

- 不提供公开注册；注册必须使用服务端签发、可失效且受使用次数约束的邀请码。
- 邀请码只用于创建账号，不能代替登录凭证、会话或 LLM API Key。
- 密码或等价认证凭证必须使用适合认证的单向算法存储，不能保存明文。
- 登录、退出、会话失效和受保护写请求必须具有可测试的安全语义；认证失败不能泄露账号是否存在。
- 产品用户不提供 Fake Interpreter。注册用户只有在服务端权限、配额和模型配置均允许时才能
  使用 LLM Interpreter；Fake Model 仅用于自动化测试、离线 Eval 和故障注入。
- 客户端传入的 Interpreter、`user_id`、`workspace_id` 或权限字段不具有授权效力。
- LLM 不可用、配额耗尽或调用失败时必须明确失败，不能静默降级为 Fake 并伪装成同等能力。
- LLM API Key 只存在于服务端配置，不进入浏览器、业务数据库、Checkpoint、日志或审计明文。
- 模型调用必须支持按用户或工作区限流、计量和停用，避免邀请码账号成为无边界成本入口。
- 客户 API 与运营 API 必须使用独立路由命名空间和可测试的权限矩阵；后台页面能够加载不代表调用者能够访问后台 API。
- 高影响运维、Backup、Restore、升级和完整 Eval 执行继续优先使用固定 CLI。运营控制台不得提供任意 Shell，也不得在单 Worker 请求内启动无界离线任务。

## 动作风险等级

| 等级 | 示例 | 默认策略 |
|---|---|---|
| R0：只读 | 查询本人订单、物流和已发布政策 | 授权与参数校验通过后自动执行 |
| R1：可撤销业务写入 | 创建 Mock Case、保存明确授权的偏好 | 展示动作摘要，按版本 Policy 执行 |
| R2：模拟资金或高影响动作 | 创建 Mock 退款、取消 Mock 订单、修改收货信息 | 必须展示具体参数并人工批准 |
| R3：特权或不可逆动作 | 绕过受控接口直接改支付记录、直接设为已退款、绕过 Policy、批量 Mock 退款 | 禁止 |

风险等级由确定性 Policy 根据工具、参数、订单状态、金额和用户权限计算，不接受 LLM 自报结果。

## Mock 退款与副作用

- 退款资格、金额、渠道和上限由确定性 Policy 计算。
- 执行退款前必须向审批者展示订单、原因、金额、渠道和风险依据。
- 每个写操作使用稳定的 `task_id`、`action_id` 和幂等键。
- LangGraph 中断恢复可能重新进入节点，中断前不得放置不可幂等副作用。
- Fake Gateway 返回成功后仍须重新查询项目内业务状态验证结果。
- 项目不得保存或调用真实支付凭据、商户密钥、支付 Token 或外部退款标识。
- 确定性演示数据入口只能维护退款前的金额、币种、渠道和支付状态；进入待审批、未知或
  完成退款后，支付事实的修改必须被限制，`refunded` 只能由 Refund Gateway 写入。
- 拒绝、超时、冲突、业务失败和未知结果必须有明确终态。

## 工具契约

每个工具必须定义：

- 单一业务职责和结构化输入 Schema。
- 结构化成功结果、业务错误和技术错误。
- 用户、订单和租户授权要求。
- 风险等级、审批要求和副作用。
- 幂等、超时、重试和取消行为。
- 执行后验证方法。
- Fake 实现以及单元或契约测试。

工具内部不接收整段隐藏 Prompt 来决定权限；权限参数必须显式且可审计。

## State 与存储

以下数据必须分离：

| 数据 | 用途 | 建议存储 |
|---|---|---|
| 公开会话与消息 | 用户可见历史、列表、分页和删除 | 独立产品会话存储 |
| Task/Agent State | 内部消息、待补信息、动作和恢复点 | LangGraph Checkpointer |
| 账号、邀请与访问会话 | 身份认证和服务端权限 | 独立认证/业务存储 |
| Mock 订单、物流、支付、退款和 L2 Case | 项目内业务事实 | 独立本地业务数据库或 Repository |
| 售后政策原文 | 可发布的知识来源 | 文档存储 |
| RAG 索引 | 从政策文档派生的检索数据 | 可重建索引 |
| 用户长期记忆 | 经用户同意保留的偏好 | 独立 Store |
| Audit/Eval | 工具、审批、结果和指标 | 独立审计与评测存储 |

- State 不保存 API Key、数据库连接、模型客户端或不可序列化对象。
- Checkpoint 不作为登录会话、邀请码、账号、订单或物流数据库。
- Checkpoint 也不直接作为面向浏览器的聊天历史 API；公开历史只能包含经过服务端投影的
  用户消息、助手消息、引用和动作状态。
- Mock 支付、退款和 L2 Case 记录同样属于业务事实，不能写入 Checkpoint 或 RAG 索引。
- State Schema、节点名称和 Checkpoint 格式按持久化接口管理。
- 修改持久化接口前必须说明兼容和迁移方案。
- 删除公开会话、Checkpoint、长期记忆、业务事实、审计和 RAG 索引必须具有独立语义。
- 完整演示空间重置必须经过显式确认，按版本恢复基准事实并清理该工作区中的派生业务事实、
  公开会话、Checkpoint 与长期记忆；Agent 和模型输出不能触发重置。
- 长期记忆只能保存用户明确确认的稳定低风险信息；不能静默提取，也不能覆盖最新业务
  工具结果、Policy、权限或风险等级。
- 用户必须能够查看、纠正和删除本人长期记忆；不同用户和工作区的记忆严格隔离。

## Agent Loop

- 固定流程优先使用确定性工作流，不为展示框架强行使用 Agent Loop。
- Agent Loop 只用于需要“观察、选择工具、执行、再观察”的复杂售后任务。
- 每次循环只能产生结构化的回复、工具候选或停止决定。
- 每个任务必须限制最大步骤、时长、模型调用、工具调用和成本。
- 必须定义成功、失败、拒绝、升级、冲突和预算耗尽终态。
- v0.5 只允许一个明确披露的 L2 Agent；没有 Eval 证明单 Agent 不足前，不引入更多 Agent
  或 Supervisor。
- Agent Loop 只能调用服务端注册的类型化工具；R1/R2 动作仍执行相应确认和审批，模型不能
  因位于循环中而获得额外权限。

## RAG

- 只有政策问答需求进入对应版本后才建立 RAG。
- 回答必须保留来源、文档版本和可定位片段。
- 检索内容不能授权退款或覆盖确定性 Policy。
- 索引必须可根据原始文档重建，并能识别过期版本。
- 通过固定问题集衡量检索命中、引用和最终回答正确性后，才能增加混合检索或 Rerank。

## 数据、隐私与审计

- 默认本地开发和最小化记录敏感数据。
- API Key、支付凭据和完整个人信息不得进入 Prompt、Checkpoint、日志或 Git。
- 审计记录至少包含 task/action 标识、工具、脱敏参数、风险、审批、耗时、结果和验证状态。
- 默认不记录模型隐藏推理或完整敏感工具输出。
- 运行时数据库、索引、日志和 Eval 产物不得提交代码仓库。

## 测试与 Eval

- 单元测试覆盖 Schema、Reducer、Policy 和纯业务规则。
- 图测试覆盖路由、补充信息、审批、拒绝、失败和恢复。
- 工具测试使用 Fake 适配器验证参数、权限、错误和幂等性。
- 集成测试使用临时数据库验证用户/thread 隔离和跨进程恢复。
- Web 测试覆盖刷新、路由切换、历史分页、重复消息、进行中 Run 和 Pending Action 恢复。
- 安全回归覆盖越权订单查询、Prompt Injection、重复退款和伪造工具结果。
- Eval 记录数据集、模型、Prompt、工具和代码版本。
- 确定性业务结果使用程序断言；LLM-as-judge 不能单独决定发布。
- 客户路由与运营路由必须分别覆盖匿名、客户、后台授权和越权访问；客户身份访问运营数据的数量必须为 `0`。
- Agent Monitoring 观察真实 Run 的脱敏运行事实，Agent Eval 使用固定数据集比较候选版本；两者必须分别标识数据来源，不能用线上监控摘要冒充发布门禁。

## 全局完成标准

- 模型不能绕过工具、Policy 或审批直接改变业务状态。
- 未授权订单数据泄露和未批准模拟资金动作数量为 `0`。
- 未登录访问者触发业务工具、会话创建或模型调用数量为 `0`。
- 恢复、重试或重放不会产生重复副作用。
- 页面刷新、路由切换和重新登录不会丢失当前身份有权访问的公开会话历史。
- 任务完成声明有项目内已持久化且重新读取的 Mock 业务状态支持。
- 无法由一级流程安全完成的任务能够明确失败或进入受控 AI 深度处理，不能伪装为真人
  Handoff。
- 每个版本提供可重复测试、Eval 证据、运行说明和已知限制。
