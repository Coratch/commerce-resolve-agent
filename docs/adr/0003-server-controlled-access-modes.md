# ADR-0003：服务端控制访问模式与私有演示工作区

状态：Accepted  
日期：2026-07-17

## 背景

v0.1 和 v0.2 通过可信本地 CLI 显式传入 `user_id`、`thread_id` 和 Interpreter，订单
与物流仍由 Fake Gateway 提供。v0.3 将产品扩展为 Web 服务：游客免费体验，受邀用户
维护私有演示数据并使用 LLM。

浏览器请求不可信。如果继续允许客户端选择身份、工作区或 Interpreter，会导致跨用户
数据泄露、游客绕过 LLM 成本控制，以及模型权限与业务授权混淆。

## 决定

- 建立游客和受邀注册用户两种服务端访问模式。
- 游客绑定共享只读演示工作区并固定使用 Fake Interpreter。
- 受邀注册用户绑定私有演示工作区；只有服务端权限、配额和模型配置允许时才能使用 LLM。
- Web 层从可信认证上下文生成 `user_id`、`workspace_id` 和访问模式，再把这些值注入核心运行时。
- 客户端提供的身份、工作区、Interpreter 或权限字段不具有授权效力。
- 注册用户通过确定性管理能力维护自定义订单和物流；Agent 在 v0.3 中只读取业务数据。
- 邀请码只用于注册，不充当登录会话或模型凭证。
- 当前 CLI 继续作为可信本地开发与 Eval 入口，其显式 Interpreter 参数不对 Web 开放。
- 身份、邀请和业务数据独立于 LangGraph Checkpoint 与政策索引存储。

本 ADR 只确定访问与信任边界。Web 框架、认证协议、数据库库和页面技术由 v0.3
Technical Plan 选择。

## 备选方案

- 所有用户都使用 LLM：体验一致，但游客可以无边界消耗模型费用，也无法验证模型授权。
- 客户端选择 Fake 或 LLM：实现简单，但客户端可以绕过成本与权限策略。
- 游客和注册用户共享同一可写数据集：演示方便，但无法证明数据归属和多用户隔离。
- 为两种模式维护两套 Graph：边界直观，但会复制订单、政策、安全和 Eval 逻辑并产生行为漂移。
- 先实现退款再补身份：短期代码更少，但退款审批和业务数据归属随后需要重构。

## 结果与代价

- 同一核心 Graph 可以复用，具体 Interpreter 和 Repository 由可信运行时装配。
- 注册、会话、邀请码、工作区和模型配额成为需要测试的新领域边界。
- 游客体验受 Fake Interpreter 表达覆盖限制，但不会产生真实 LLM 成本。
- 自定义订单和物流明确属于演示工作区，不代表真实客户可以修改平台业务数据。
- 原路线中的退款能力顺延到 v0.4，避免在身份和数据边界建立前开放资金动作。
