# v1.0–v1.3 单机运维手册

状态：Candidate  
适用版本：`1.0.0`–`1.3.0`  
参考环境：Ubuntu 24.04 LTS、Docker Engine、Docker Compose v2

## 1. 支持边界

参考部署只有一个 FastAPI 容器、一个 Uvicorn worker 和一个宿主 `var/` 数据目录。宿主端口
只绑定 `127.0.0.1`。订单、支付和退款始终是本地 Mock 数据；此手册不提供公网 HTTPS、真实
支付、多实例、高可用或在线热备份方案。

唯一宿主入口是 `./deploy/commerce-resolve`。应用级固定运维入口是
`python -m commerce_resolve ops ...`。不要直接复制正在运行的 SQLite 文件，也不要手工修改
`instance.json`、Backup Manifest 或 `.git` 内数据。

## 2. 首次安装

```bash
cp .env.deploy.example .env.deploy
mkdir -p var
sudo chown -R 10001:10001 var

./deploy/commerce-resolve build
./deploy/commerce-resolve up
./deploy/commerce-resolve status
```

`up` 会先幂等执行 `ops init`，再等待 `/api/health/ready`。浏览器访问
`http://127.0.0.1:8000`。默认 `LLM_FEATURE_ENABLED=false`，游客、Mock 退款和政策 RAG 核心
能力仍可 Ready；启用 LLM 时必须在未提交的 `.env.deploy` 中完整配置三个 `LLM_*` 变量。

## 3. 日常生命周期

```bash
./deploy/commerce-resolve up
./deploy/commerce-resolve status
./deploy/commerce-resolve logs
./deploy/commerce-resolve restart
./deploy/commerce-resolve down
```

- `status` 只返回发布版本、实例身份、锁状态、能力状态、有限表计数和稳定失败码。
- `restart` 强制重新创建容器并等待 Readiness，不会把已运行容器误判为完成重启。
- `down` 发送 SIGTERM，并给应用 40 秒容器宽限；应用内部宽限为 30 秒。
- 宽限后仍未完成的 Run 会在退出或下次启动时变为 `interrupted`，不会自动重放模型、工具、
  Memory 或 Mock 退款副作用。

## 4. 健康与诊断

```bash
curl -fsS http://127.0.0.1:8000/api/health/live
curl -fsS http://127.0.0.1:8000/api/health/ready
./deploy/commerce-resolve status
./deploy/commerce-resolve logs
```

- Live 只证明进程存活，不访问数据库或 Provider。
- Ready 只读检查 Instance Manifest、业务迁移、Checkpoint、Memory、政策索引和前端版本。
- LLM 是可选 Capability；配置不完整时部署 Preflight 失败，禁用时明确显示 `disabled`。
- JSON 日志包含 event、level、request/run/action ID、耗时和稳定错误码，不记录消息正文、完整
  Prompt、Cookie、邀请码、API Key 或用户主目录。
- `var/operations.jsonl` 只保存有限、脱敏的本机运维结果，并轮转一个历史文件。

## 5. Backup 与校验

正式 Backup 必须让应用停止。脚本会记录服务原状态：原本运行时自动停止并在成功后重启，
原本停止时完成 Backup 后仍保持停止：

```bash
./deploy/commerce-resolve backup
./deploy/commerce-resolve backup-verify <backup_id>
```

Backup Set 位于 `var/backups/<backup_id>/`，只包含：

- `business.sqlite`
- `checkpoints.sqlite`
- `memory.sqlite`
- `instance.json`
- `backup-manifest.json`

政策索引、日志、`.env`、密钥、Eval Artifact 和前端资源不进入 Backup。校验包括文件集合、
大小、SHA-256、SQLite `integrity_check` 和三类权威存储的有限领域计数；任何额外文件都会
使整个 Backup Set 校验失败。

## 6. Restore

空目标恢复：

```bash
./deploy/commerce-resolve down
# 把已验证 Backup Set 放入目标实例的 var/backups/
./deploy/commerce-resolve restore <backup_id>
```

空目标会生成新的 `instance_id`，并记录 `restored_from`。恢复后政策索引从镜像内版本化政策源
重建。

覆盖现有实例必须同时提供 `--replace` 和当前实例 ID：

```bash
./deploy/commerce-resolve status
./deploy/commerce-resolve restore <backup_id> \
  --replace --confirm-instance-id <current_instance_id>
```

覆盖前会在 `var/backups/rollback/` 自动创建回滚 Backup。摘要或 SQLite 完整性失败时，目标
文件不会被修改。

## 7. 升级

升级只支持停止状态，并沿已发布 Alembic 链升级到当前 `1.3.0`：

```bash
./deploy/commerce-resolve down
./deploy/commerce-resolve upgrade
```

升级顺序是：取得实例锁、创建并验证 `pre-upgrade` Backup、迁移业务库、验证
Checkpoint/Memory、重建政策索引，最后才原子更新 Instance Manifest。任何中途失败都会让服务
保持停止；成功版本不会提前写入。修复原因后可重试，或使用升级前 Backup 显式恢复。

## 8. 常见失败码

| 错误码 | 含义 | 处理 |
|---|---|---|
| `release_manifest_invalid` | 镜像版本、前端、迁移或基线不一致 | 重新使用同一提交构建镜像 |
| `public_host_not_loopback` | 试图将参考部署公开到非回环地址 | 恢复 `127.0.0.1`；公网部署不在支持范围 |
| `llm_configuration_incomplete` | 启用 LLM 但三个变量不完整 | 补齐变量或关闭 LLM |
| `instance_lock_held` | 服务或另一运维命令正在使用实例 | 先停止服务，不删除锁文件绕过 |
| `*_not_ready` | 存储、索引或前端版本未就绪 | 查看 `status` 和 JSON 日志，不手工建空库 |
| `backup_file_digest_mismatch` | Backup 内容与清单不一致 | 丢弃损坏副本，使用另一份已验证 Backup |
| `restore_instance_confirmation_required` | 覆盖恢复身份确认不匹配 | 重新读取当前 instance ID 后显式确认 |
| `upgrade_source_not_v08` | 数据来源不是受支持 v0.8 | 不强制升级，先恢复受支持数据 |

## 9. 发布验收

```bash
python -m commerce_resolve eval run
python -m commerce_resolve eval release \
  --baseline data/eval/baselines/offline-v1.3.json
```

发布门禁覆盖后端、Ruff、依赖、373 条离线 Eval、迁移、OpenAPI、前端、两类浏览器场景、
Bundle、安全扫描和 Docker Compose 配置。Docker 不可用时容器检查必须为 `incomplete`，不能
用静态测试冒充通过。

v1.2 起管理员角色只能由宿主 CLI 管理：

```bash
python -m commerce_resolve admin grant <username>
python -m commerce_resolve admin list
python -m commerce_resolve admin revoke <username>
```

不要从数据库直接修改角色，也不要把 Web 管理员视为宿主维护者；Backup、Restore、Upgrade、
Reconcile 和完整 Eval 仍只允许固定 CLI。
