# Technical Plan：v2.0 可演示、可评估的智能售后 Agent 产品

状态：Completed  
日期：2026-07-24  
对应 Spec：
[`../specs/v2.0-interview-ready-agent-product.md`](../specs/v2.0-interview-ready-agent-product.md)

## 1. Plan 目标

本 Plan 把已接受的 v2.0 产品行为拆成可验证的垂直任务。实现重点不是重写现有 Agent，而是把
v0.1–v1.3.2 已验证的能力收敛到一个邀请制、订单绑定、可重置、可演示的产品闭环：

```text
邀请注册
→ 原子创建版本化演示工作区
→ 售后中心选择订单
→ 恢复或创建单订单 Thread
→ 查询订单/物流/政策
→ 确定性退款 Policy
→ interrupt 客户确认
→ 幂等 Mock 退款
→ 业务回读验证
→ Agent Run、Memory、RAG 与 Eval 证据
```

## 2. 当前基线与复用边界

已通过的实现继续复用：

- SQLite 业务库、Alembic、邀请注册、Session、CSRF 和 Origin 校验。
- LangGraph State、Checkpoint、公开消息、Run、SSE 和断线恢复。
- 订单、物流、Mock 支付、退款、L2 Case 和长期偏好 Repository。
- FTS5 政策检索、引用、确定性退款 Policy、`interrupt` 和幂等 Executor。
- 售后首页、订单/服务读模型、管理员 Monitoring、Eval 与系统健康。
- React + TypeScript、React Query、Lucide、既有响应式设计系统。

v2.0 不重写以上已验证的领域能力，只改变其产品入口、数据生命周期和权限组合。

基线证据：

- TypeScript 基线：类型检查通过。

## 3. 关键技术决策

### 3.1 保持模块化单体与四类存储职责

继续使用 FastAPI、React、SQLAlchemy、SQLite 和 LangGraph。业务事实、Checkpoint、政策索引与
Eval Artifact 保持分离。v2.0 不引入微服务、消息队列、PostgreSQL 或向量数据库。

### 3.2 注册初始化必须使用同一个业务事务

注册用例在一个 SQLAlchemy 事务中完成邀请码消费、账号和工作区创建、三个场景基准事实写入及
Workspace Ready 标记。任何步骤失败都回滚账号、工作区、订单和邀请码使用计数。

### 3.3 版本化演示数据复用现有商品资产

新增 `portfolio-demo-v1` Manifest，只声明三个面试场景及其业务基准，不复制运行时商品主档。
场景引用 v1.3 已校验的本地商品资源和 SKU，注册时写成订单快照。公开订单号由
`CR-XXXX-XXXX` 生成器产生，内部 UUID 和隐藏 `scenario_key` 继续分离。

### 3.4 工作区重置采用受锁、幂等的协调服务

SQLite 单机版本使用进程内工作区锁和可重入 Reset Service。业务库事务清除派生事实并按原订单号
重建三个基准场景；之后删除对应 LangGraph Checkpoint。Checkpoint 删除失败时工作区保持非
Ready，重复调用继续协调，不开放新的售后写操作。

### 3.5 匿名访问不再创建游客 Session

`GET /api/session` 对匿名浏览器返回无凭据的 `anonymous` 能力投影，不创建 Cookie、工作区或
Guest 数据。所有业务、会话、Memory、Run 和模型入口以服务端注册身份门禁为准。

### 3.6 一个活动订单任务对应一个 Thread

创建会话 API 必须提供服务端可验证的本人订单号。Repository 通过
`workspace_id + order_id + lifecycle_status=active` 恢复活动 Thread；无活动任务时才创建。
归档后再次咨询创建新 Thread。数据库唯一部分索引阻止并发重复创建。

### 3.7 前端只消费结构化业务事件

自然语言继续通过公开消息流式展示。订单、物流、政策、退款预览、确认和回执继续使用版本化
Payload 和类型化组件；前端不从 Markdown 解析金额、状态或按钮。悬浮 Agent 只是现有核心
会话接口的全局客户端。

### 3.8 管理员只管理演示空间

移除管理员和客户 Web 订单 CRUD 路由及前端入口；内部 Repository 写方法保留给注册初始化、
重置、测试和受控 Agent 工具。Web 端不提供角色授予、客户冒充或直接退款。

## 4. 数据模型与迁移

新增 Alembic `0009`：

- `workspaces.dataset_version`：当前演示数据版本。
- `workspaces.dataset_status`：`initializing | ready | resetting | failed`。
- `workspaces.reset_generation`：幂等重置代数。
- `workspaces.initialized_at`：最近一次成功初始化时间。
- `workspace_reset_audit`：目标工作区、操作者、代数、结果和脱敏时间。
- 活动单订单 Thread 的唯一部分索引。

兼容策略：

- 既有账号和角色原样保留。
- 既有工作区版本为空，不自动覆盖；显式重置后进入 `portfolio-demo-v1`。
- 既有未绑定订单会话保持只读历史；不与 v2.0 活动任务复用。
- 既有退款、服务、审计和 Eval 行不改写。

## 5. 后端接口

### 5.1 公开与认证

```text
GET  /api/session
POST /api/auth/register
POST /api/auth/login
POST /api/auth/logout
```

- 匿名 Session 响应为 `anonymous`，无 CSRF 和业务能力。
- 注册成功只返回账号结果；用户登录后进入 `/support`。
- 登录、注册不依赖游客 Session；写请求仍验证受信 Origin。

### 5.2 演示工作区

```text
GET  /api/demo-workspace
POST /api/demo-workspace/reset
POST /api/admin/customers/{user_id}/demo-workspace/reset
```

重置请求包含客户端稳定请求 ID 和明确确认字段；服务端不接受订单、状态或金额参数。

### 5.3 订单任务

```text
POST /api/conversations
GET  /api/conversations
GET  /api/conversations/{thread_id}
PATCH /api/conversations/{thread_id}
```

- 创建请求中的 `related_order_id` 变为必填 `CR-XXXX-XXXX`。
- 创建结果增加 `created`，区分恢复和新建。
- Chat、审批、重试继续按已授权 Thread 执行。

### 5.4 运营控制台

保留邀请、客户工作区、Run、Eval、政策和系统健康接口；删除 Web 订单、物流、支付和退款 CRUD。

## 6. 前端产品结构

```text
Public
├── Landing /
├── Login /login
└── Invitation Register /register

Customer
├── Support Home /support
├── Orders /support/orders
├── Order Detail /support/orders/:orderId
├── Services /support/services
├── Memories /support/memories
├── Demo Settings /support/settings
└── Global Order-bound Agent Drawer

Admin
├── Overview
├── Invitations
├── Demo Workspaces
├── Agent Runs
├── Eval
└── System / Policy status
```

- 未登录访问业务路由时重定向登录。
- 桌面 Agent 从右侧抽屉展开；移动端使用全屏层。
- 全局入口无订单上下文时展示订单选择，不创建会话。
- 从订单卡打开时绑定订单并恢复活动 Thread。
- 抽屉状态由 Customer Layout 持有，路由切换不卸载。
- 普通 Agent 失败作为对话消息展示；认证和服务整体故障保留页面级状态。

## 10. 风险与控制

| 风险 | 控制 |
|---|---|
| 注册 Seed 与账号事务分离 | 同一事务写入全部基准事实，故障注入验证回滚 |
| 重置跨业务库与 Checkpoint 非原子 | Resetting 状态、稳定 generation、幂等协调与失败续跑 |
| 两个请求创建重复订单 Thread | 数据库唯一部分索引和 Repository 恢复语义 |
| 旧 Guest 代码重新暴露 | 匿名零 Cookie、所有业务路由注册门禁和固定安全 Eval |
| 管理员 CRUD 绕过 Agent | 删除公开路由与页面，Repository 只保留内部服务调用 |
| 公共订单号碰撞 | 安全随机字符集、工作区唯一约束和有限重试 |
| 场景键泄露给模型或客户 | 只存内部列；公开 Schema、Prompt 和 Payload 排除 |
| UI 重构破坏 Agent 状态 | 复用现有会话 Hook、SSE 和服务端 Task 事实 |
| 资金规则被 RAG/模型覆盖 | Policy 读取权威事实与规则版本，RAG 仅提供解释证据 |
| v2.1 能力提前进入 | v2.0 继续 FTS5；不增加上传、向量、多模态和 Rerank |
