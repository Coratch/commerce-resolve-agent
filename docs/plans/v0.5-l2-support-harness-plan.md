# Technical Plan：v0.5 LLM 二线客服 Agent Harness

状态：Completed  
日期：2026-07-19  
接受日期：2026-07-20  
完成日期：2026-07-20  
对应 Spec：[`../specs/v0.5-l2-support-harness.md`](../specs/v0.5-l2-support-harness.md)  
关联决策：[`../adr/0006-llm-l2-support-harness.md`](../adr/0006-llm-l2-support-harness.md)

## 1. Plan 目标

在保持 v0.1–v0.4 一线订单、物流、政策 RAG、Web 身份和 Mock 退款行为不变的前提下，
增加一个明确标注为 AI、由受控 Harness 驱动的二线客服：

- 受邀用户先看到升级预览，确认前不创建 L2 Case，也不调用 L2 模型。
- 确认后创建可恢复的 L2 Support Case，并装配最小可信上下文。
- L2 模型每一步只返回一个经过 Pydantic 校验的结构化决策。
- Harness 通过固定 Tool Registry、确定性 Policy 和预算执行 R0 工具。
- 信息不足时使用 `interrupt` 暂停，用户补充后从同一 Case 恢复。
- L2 提出的 Mock 退款复用 v0.4 的预览、审批、幂等执行和回读验证。
- L2 只能建议保存受限偏好，用户确认后才写入独立长期记忆 Store。
- Case 状态、公开 Trace、模型用量和停止原因可以查询和离线评估。

本 Plan 只解决已接受 Spec 中的单个 L2 Agent。真实人工客服、多 Agent、任意网络工具、
新向量库和生产异步 Worker 不进入实现。

## 2. 成功标准

实现完成后必须能够复现以下端到端路径：

```text
受邀用户提出复杂售后问题或明确要求升级
  -> 一线 Interpreter 只识别升级诉求和可选订单号
  -> 确定性 L2UpgradePolicy 判断是否允许展示升级
  -> 页面展示“AI 二线客服、并非真人”、上下文、工具和预算
  -> 用户确认
  -> 创建 L2 Support Case
  -> L2 Agent 读取订单 + 物流 + 政策等至少两类证据
  -> 根据 Observation 决定继续调用工具、询问用户或形成结论
  -> 保存公开结果、Trace、预算和停止原因
```

同时满足：

- 游客、越权用户、取消升级和未确认升级的 L2 模型调用、Case 与记忆写入均为 `0`。
- 每个模型步骤只对应一种合法决策；未知工具、非法参数和越权作用域不会执行。
- 页面或服务重启后可以恢复升级确认、补充信息、记忆确认和退款审批。
- Case 不超过固定步骤、模型调用、工具调用、活跃时长和估算 Token 预算。
- 无进展重复和连续工具失败提前停止，不形成无限循环。
- 未确认长期记忆写入数为 `0`；用户能查看、纠正和删除本人记忆。
- L2 建议退款后仍由 v0.4 Policy 生成预览，用户未批准时退款写入数为 `0`。
- 重试、节点重放和恢复不会重复创建 Case、Trace、记忆或 Mock 退款。
- 公开 Trace 不包含完整 Prompt、隐藏推理、密钥或无关业务正文。
- v0.5 固定 30 个场景达到 `30/30`，v0.1–v0.4 全部回归。

## 3. 当前基线与实施约束

v0.4 已提供：

- FastAPI 同源内部 JSON API、React + TypeScript SPA。
- 邀请注册、服务端 Session、CSRF/Origin、conversation 归属和工作区隔离。
- 唯一 `build_workflow()`，以及订单、政策和退款节点注册模块。
- SQLite 业务库、LangGraph Checkpoint、SQLite FTS5 政策索引三类独立存储。
- R2 Mock 退款预览、`interrupt`、审批、稳定 action、幂等执行和业务回读验证。
- 注册用户的一线 OpenAI-compatible Chat Interpreter 和每日调用额度。
- 进程内 thread 锁，以及跨 thread 的数据库唯一约束。

v0.5 必须增量实现：

- 不复制第二张完整主图；L2 节点注册到现有唯一 `StateGraph`。
- 不把 L2 Case 业务事实或长期记忆塞进 Checkpoint。
- 不让模型、浏览器或长期记忆提供 `user_id`、`workspace_id`、工具白名单或预算。
- 不让 L2 模型直接调用 Repository、SQL、Python 函数、退款 Gateway 或 Memory Store。
- 不改变游客的 Fake 一线模式，也不把简单请求强制升级到 Agent Loop。
- 本地交付继续只承诺单实例、单 Uvicorn worker；持久业务唯一性仍由数据库约束保证。

当前锁定依赖已经包含 LangGraph `1.2.9`、`langgraph-checkpoint-sqlite 3.1.0` 和
OpenAI SDK `2.45.0`。前者提供 `StateGraph.compile(store=...)`，SQLite 包同时提供
`SqliteStore`。v0.5 不需要新增 Python 或 npm 运行时依赖。

## 4. 总体架构

继续采用模块化单体和同步请求模型：

```text
React Chat / Memory 页面
  -> same-origin JSON API
  -> Session / Origin / CSRF / conversation ownership
  -> Pending State Dispatcher
  -> 唯一 build_workflow()
       -> 一线确定性路径（保持现状）
       -> L2 节点模块
            Upgrade Preview / Confirmation
            Context Assembler
            Structured L2 Model
            Decision Policy
            Typed Tool Registry
            Observation / Budget / Stop
            Memory Confirmation
            v0.4 Refund Bridge
  -> Public Response / Trace

物理存储：
  var/business.sqlite       L2 Case、公开事件和模型调用计量
  var/checkpoints.sqlite    Loop 工作记忆、中断和恢复点
  var/policy-index.sqlite   现有可重建政策 FTS5 索引
  var/memory.sqlite         用户明确确认的长期偏好
```

L2 Case Repository 保存公开业务状态和最小审计事实；Checkpointer 保存“下一步从哪里继续”；
Memory Store 保存跨 Case 的低风险偏好。任何一个存储都不能代替另一个。

## 5. 技术选型

| 领域 | 选择 | 原因 |
|---|---|---|
| 编排 | 现有 LangGraph 1.2.9 唯一主图 | 直接复用 conversation Checkpoint、退款节点和恢复语义 |
| L2 组织 | 独立 `l2_workflow.py` 注册节点，不编译嵌套子图 | 保持模块边界，同时避免跨图状态映射和 `Command.PARENT` 复杂度 |
| Agent Loop | 自定义结构化 Loop | 明确控制工具、预算、审批、Trace 和停止，不接受黑盒 ReAct |
| 模型协议 | OpenAI-compatible Chat JSON Output + Pydantic v2 | 兼容现有 DeepSeek 接入并严格拒绝未知字段 |
| 测试模型 | Scripted Fake L2 Model | 离线稳定覆盖多步、失败和恢复轨迹 |
| 工具治理 | 静态类型化 Tool Registry + 确定性 Policy | 模型不能注册函数、扩大参数或改变风险 |
| Case 持久化 | 现有 SQLite + SQLAlchemy + Alembic | 与身份和 Mock 业务事务一致，保留增量迁移 |
| 工作记忆 | 现有 SQLite Checkpointer | 支持中断、服务重启和同一 thread 恢复 |
| 长期记忆 | LangGraph `SqliteStore`，关闭语义索引 | 学习 Store，并以独立文件提供作用域和删除语义 |
| 政策 RAG | 复用 Markdown + manifest + SQLite FTS5 | 当前 Eval 已证明可用，不为展示 RAG 增加向量库 |
| Web 协议 | 普通 JSON + 独立确认请求 | 暂停可能跨进程；SSE 连接不能作为持久事实 |
| 前端 | 现有 React、TypeScript、TanStack Query | 复用 Session、conversation、退款卡与 OpenAPI 类型 |
| Eval | pytest、Vitest、Playwright、固定 Fake | 对结构化轨迹和副作用作确定性断言 |

### 5.1 为什么使用一张主图而不是嵌套 Subgraph

L2 提出的退款需要进入现有 `prepare_refund_request`，审批后又要把退款结果作为 Observation
返回 L2 Loop。若把 L2 编译成独立 Subgraph，需要额外处理父子 State 映射、Checkpoint
namespace、跨图 `Command.PARENT` 和退款后的返回地址。

v0.5 采用更小的方案：

- L2 的领域模型、节点和注册函数位于独立模块。
- 所有节点仍注册到唯一 `StateGraph(AgentState)`。
- 节点名称使用 `l2_` 前缀，避免与一线节点混淆。
- 退款终端节点根据 `l2_runtime` 是否存在决定 `END` 或返回 L2 Observation。

只有以后出现可独立复用、拥有明确输入输出 Schema 的第二个 Agent 时，才重新评估
Subgraph；本版本不为展示 LangGraph 特性提前增加它。

### 5.2 为什么不使用预构建 ReAct Agent 或 `ToolNode`

v0.5 的工具不是“模型能调用就执行”：每次调用还要检查用户作用域、工具白名单、参数、
风险、预算、重复签名和公开 Trace；记忆与退款还要进入不同确认链。自定义 Loop 可以把这些
步骤作为显式节点和测试断言。

模型仍实践 Agent Loop 和工具选择，但执行权属于 Harness。等固定 Eval 证明自定义协议
成为阻碍时，才评估预构建 Agent；不能先牺牲治理边界换取少量代码。

### 5.3 为什么模型使用 JSON 决策而不是 Provider 原生 Tool Calling

现有真实接入是 OpenAI-compatible DeepSeek。v0.5 继续使用 Chat JSON Output，并将模型
结果解析为严格判别联合，避免不同 Provider 的 Tool Calling 差异进入 Graph。

这不会削弱 Agent 能力：模型仍选择受限工具和参数；只是 Harness 先验证决策，再由自己的
Registry 执行。未来迁移原生 Tool Calling 时只替换 `L2AgentModel` 适配器。

### 5.4 为什么长期记忆不使用向量检索

本版本只允许三类枚举偏好，按 `(workspace, user, type)` 精确读取即可。语义 Embedding 会
增加删除、冲突和 Prompt Injection 面，却没有召回收益。因此 `SqliteStore` 不配置
`index`；v0.2 政策 FTS5 也保持不变。

### 5.5 为什么暂不使用 SSE、队列或后台 Worker

本版本关注可恢复 Loop，而不是网络 Token 流。一次 HTTP 调用运行到回答、明确中断或停止；
等待用户时由 Checkpoint 持久化并结束请求。同步模型请求通过严格每轮调用数和时长限制
控制。本地单实例不引入队列；若实际延迟超过验收边界，再在独立 ADR 中评估 Worker/SSE。

## 7. 领域模型

所有模型使用 `ConfigDict(frozen=True, extra="forbid")`；长度、枚举和集合大小均设上限。

### 7.1 一线 Interpreter 输出

`Intent` 增加：

```text
l2_support_request
```

`Interpretation` 只允许附带：

```text
order_id: 可选
l2_issue_summary: 1..500 字符
```

它不能输出 Case ID、工具、预算、风险、记忆、退款金额或批准结果。Fake Interpreter 只识别
固定升级表达；OpenAI Interpreter Prompt 增加同一 Schema。是否允许升级仍由服务端
`L2UpgradePolicy` 决定。

分类优先级保持“能由现有一线路径完成的订单/物流、政策和明确退款请求优先”；只有用户
明确要求升级，或当前可信 State 已处于政策冲突、退款未知/验证不一致、售后域未支持等
允许状态时，才形成 L2 candidate。模型分类只是候选，Policy 还会验证可信状态、身份、
配额和当前中断。

### 7.2 L2 模型输入

```text
L2ModelRequest
  case_id / step_id
  issue_summary
  latest_user_input
  related_order_id | null
  recent_public_messages[]
  observations[]
  confirmed_preferences[]
  allowed_tools[]
  remaining_budget
```

- 输入不包含用户、工作区、数据库主键、凭据或可执行函数对象。
- 上下文装配后整体最多 `12_000` 字符。
- 工具结果只以经过校验和截断的 Observation 进入。
- 系统指令、工具契约、用户文本、政策和记忆使用明确 JSON 字段分隔。

### 7.3 L2 结构化决策

使用 `kind` 判别联合，每步只能出现一种：

```text
ToolCallDecision
  kind=tool_call
  call: GetOrder | GetShipment | GetRefundStatus | SearchPolicy | ListPreferences

AskUserDecision
  kind=ask_user
  question: 1..300 字符
  expected_field: order_id | refund_reason | product_context | clarification

ProposeRefundDecision
  kind=propose_refund
  order_id
  reason: 现有 RefundReason

ProposeMemoryDecision
  kind=propose_memory
  memory_type
  value: 受限枚举
  purpose: 固定公开用途文案

AnswerDecision
  kind=answer
  answer: 1..1200 字符
  evidence_ids[]

StopDecision
  kind=stop
  reason: unsupported | insufficient_evidence | safety_rejected | model_limit
  public_message
```

模型不输出节点名、Python 名称、任意工具名、SQL、URL、身份、风险或审批状态。Harness 为
合法决策分配稳定 `step_id`、`decision_id` 和动作标识。

### 7.4 Observation 与工作 Runtime

```text
L2Observation
  observation_id
  step_id
  source_type
  source_ref
  result_code
  summary
  evidence_ids[]
  observed_at

L2BudgetState
  steps_used
  model_calls_used
  tool_calls_used
  estimated_tokens_used
  active_milliseconds
  consecutive_tool_failures
  last_action_signature | null
  repeated_action_count

L2RuntimeState
  preview_id | null
  case_id | null
  phase
  issue_summary
  related_order_id | null
  allowed_tools[]
  observations[]
  pending_decision | null
  pending_memory_proposal | null
  budget
  final_response | null
  stop_reason | null
```

`AgentState` 只增加可选 `l2_runtime` 和 `l2_upgrade_preview`。Runtime 每个节点返回完整的新
不可变值，不原地修改；Observation 最多保留当前 Case 必需的有界摘要，大型正文按来源
重新读取。

### 7.5 公开 Trace

```text
L2PublicTraceEvent
  event_id
  case_id
  step_number
  event_type
  tool_category | null
  parameter_summary | null
  result_code
  evidence_ids[]
  duration_ms
  created_at
```

`parameter_summary` 由工具适配器根据白名单字段生成，不序列化原始 Model Request。公开
Trace 不保存 Prompt、Chain-of-thought、Cookie、API Key 或完整工具正文。

### 7.6 长期记忆

v0.5 只允许：

| `memory_type` | 合法值 |
|---|---|
| `preferred_language` | `zh-CN`、`en` |
| `response_detail` | `concise`、`standard`、`detailed` |
| `communication_tone` | `neutral`、`friendly` |

```text
CustomerPreference
  memory_id
  memory_type
  value
  source_case_id
  schema_version
  created_at
  last_confirmed_at
```

不保存任意自由文本、订单、物流、支付、退款、政策结论或模型推断。相同类型使用稳定 Store
key，用户明确纠正时覆盖该类型；删除是独立操作。

## 8. Agent Loop 与图结构

### 8.1 升级入口

一线 `bind_and_interpret` 得到 `l2_support_request` 后，路由到：

```text
l2_prepare_upgrade
  -> L2UpgradePolicy
  -> l2_await_upgrade_confirmation (interrupt)
       ├─ cancel -> l2_cancel_upgrade -> END
       └─ confirm -> l2_create_case -> l2_load_context
```

升级 Policy 必须同时验证：注册身份、conversation 归属、LLM 能力、配额可用、售后领域、
没有冲突中断、没有同 thread 活动 Case。预览中的工具和预算由服务端产生；浏览器只提交
`preview_id` 和 `confirm|cancel`。

一线请求接受模型调用后，Web 把服务端重新读取的剩余每日额度作为只读 RunContext 能力
注入升级 Policy。确认请求还要再次读取当前模型配置、账号状态和剩余额度；两次请求之间
若额度耗尽或权限被关闭，确认失败且不创建 Case。

确认前仅允许一线 Interpreter 已发生的一次模型调用；L2 模型调用和 Case 写入为 `0`。
取消只更新 Checkpoint 中的公开结果，不创建业务 Case。

### 8.2 Loop 主路径

```text
l2_load_context
  -> l2_decide
  -> l2_validate_decision
       ├─ tool_call       -> l2_execute_tool -> l2_record_observation -> l2_decide
       ├─ ask_user        -> l2_await_user_input (interrupt) -> l2_record_user_input -> l2_decide
       ├─ propose_memory  -> l2_await_memory_confirmation (interrupt)
       │                       ├─ reject -> l2_record_observation -> l2_decide
       │                       └─ confirm -> l2_write_memory -> l2_record_observation -> l2_decide
       ├─ propose_refund  -> l2_bridge_refund -> 现有 v0.4 退款链
       ├─ answer          -> l2_finalize_resolved -> END
       └─ stop/invalid    -> l2_finalize_stopped -> END
```

每次 `l2_decide` 前检查预算并创建稳定 Step；每次返回后只持久化结构化决策和公开摘要。
模型不可用、输出不合法或配额耗尽不会切换 Fake，而是进入明确停止状态。

### 8.3 用户补充信息

`l2_await_user_input` 使用 `interrupt` 保存公开问题。用户继续使用现有聊天输入框，但 Web
在调用图前读取 `StateSnapshot.next`：

- 若为 `l2_await_user_input`，构造 `Command(resume={message})`。
- 使用不允许调用一线 Interpreter 的恢复依赖。
- 校验输入长度、Session、conversation、Case 归属和 thread 锁。
- 把补充内容追加为用户消息，再进入下一次 L2 决策。

其他待确认状态收到普通消息时返回 `409`，不能把自由文本误当批准决定。

### 8.4 停止状态

公开状态至少包括 Spec 中的状态，并映射到业务 Case：

```text
l2_awaiting_confirmation
l2_active
l2_waiting_user
l2_waiting_approval
l2_resolved
l2_unresolved
l2_budget_exhausted
l2_cancelled
l2_stopped
```

`l2_finalize_*` 先幂等更新 Case 和公开事件，再返回面向用户的消息。模型的 `answer` 只有在
引用的 evidence IDs 均存在、且必要业务事实来自工具时才可进入 `l2_resolved`；否则降为
`l2_unresolved`。

终态 Runtime 暂留在当前 Checkpoint 以构造最后一次公开响应；下一条不属于恢复操作的新
消息由 `bind_and_interpret` 清理终态 Runtime。业务 Case 与 Trace 仍在 Repository 中可查。
退款返回 L2 的条件不仅检查 `case_id`，还要求 Runtime 处于活动阶段且 action 来源绑定该
Case，防止后续普通退款误回到已结束的 Loop。

## 9. Tool Registry 与确定性 Policy

v0.5 固定注册以下 R0 工具：

| 工具 | 输入 | 结果来源 | 额外限制 |
|---|---|---|---|
| `get_order` | `order_id` | 现有 OrderGateway | 强制当前 BusinessScope |
| `get_shipment` | `order_id` | 现有 LogisticsGateway | 必须重新验证订单归属 |
| `get_refund_status` | `order_id` | 现有 RefundGateway | 只读 action/refund 验证摘要 |
| `search_policy` | 受限 PolicyQuery | 现有 FTS5 Repository | 服务端固定 limit，保留引用 |
| `list_confirmed_preferences` | 无 | 当前用户 Store namespace | 只返回三类已确认偏好 |

实现规则：

- Registry 是代码中的不可变映射，工具名使用 `Literal`，不提供运行时注册 API。
- Tool Request 使用判别联合；模型不能传 user/workspace、SQL、limit、路径或网络参数。
- Policy 在每次执行前重新计算工具是否在 Case 白名单、作用域是否合法、预算是否足够。
- 工具 handler 接收服务端 `RunContext`，忽略模型中的身份声明。
- 工具结果先通过 Pydantic 和归属检查，再压缩为最多 `3_000` 字符的 Observation。
- 读取失败是结构化结果，不把异常堆栈交给模型。
- 相同工具 + 规范化参数形成 action signature；没有新用户输入或新 Observation 时重复一次即
  判定无进展并停止。
- 连续两次工具失败停止；R0 读取不自动重试，避免隐藏增加调用和延迟。

Prompt、政策片段、订单备注、工具错误和记忆中的文本都标记为数据。即使包含“调用某工具”
等文字，也不能跳过 Model Decision Schema 和 Tool Policy。

## 10. 退款桥接

L2 `ProposeRefundDecision` 只表示候选意图，不是退款授权。桥接步骤：

1. 校验订单号和 `RefundReason` Schema，并确认订单属于当前工作区。
2. 把候选写入现有 `order_id`、`refund_reason` 和 `pending_refund_request` State。
3. 路由到现有 `prepare_refund_request`，由 v0.4 重新读取业务事实和政策。
4. 不符合资格、冲突或失败结果转换为 L2 Observation，Loop 可解释或安全停止。
5. 符合资格时继续生成现有 R2 `RefundPreview` 并在 `await_refund_approval` 暂停。
6. 浏览器继续使用现有退款批准接口，L2 Agent 没有批准字段。
7. 拒绝、过期、完成、未知或验证失败转换为 L2 Observation，再由 L2 决定最终回复。

为保持 v0.4 兼容，退款终端路由根据 `l2_runtime.case_id` 分流：

```text
普通一线退款 -> 现有回复 -> END
L2 候选退款   -> 现有回复/结果 -> l2_record_refund_observation -> l2_decide 或安全停止
```

不复制 Refund Policy、Gateway、审批 API 或执行表。`action_id`、fingerprint、幂等键和
Verifier 全部沿用 v0.4。

## 11. 循环预算、模型计量与成本边界

默认配置：

```text
L2_MAX_STEPS=8
L2_MAX_MODEL_CALLS=6
L2_MAX_TOOL_CALLS=8
L2_MAX_ACTIVE_SECONDS=120
L2_MAX_INVOCATION_SECONDS=45
L2_MODEL_TIMEOUT_SECONDS=15
L2_MAX_ESTIMATED_TOKENS=30000
L2_CONTEXT_MAX_CHARS=12000
L2_TOOL_RESULT_MAX_CHARS=3000
L2_MODEL_MAX_OUTPUT_TOKENS=800
L2_MAX_CONSECUTIVE_TOOL_FAILURES=2
```

- “活跃时长”只累计正在运行 Graph/模型/工具的时间，不把用户等待确认的时间算入。
- 单次 HTTP 恢复最多运行 `45` 秒；达到限制时保存状态并安全停止，不启动后台任务。
- 每次模型调用 timeout 为 `15` 秒；剩余 invocation 时间不足以完成一次调用时不再启动。
- 模型调用前按当前上下文和最大输出计算保守 Token 预算；响应有 provider usage 时用真实值，
  没有时保留估算值。
- Token 上限是供应商无关的成本门禁；金额成本只作为 Eval 报告派生指标，不在代码中写死
  易过期的 Provider 单价。
- 每次 L2 模型尝试都计入现有每日调用额度，失败调用也计数；用户一次 HTTP 请求可能包含
  多个受预算限制的 L2 模型步骤。
- Case 模型调用数从业务计量记录和 Checkpoint 交叉检查，服务重启不能重置预算。

新增 `ModelCallMeter` 在真正调用 Provider 前原子登记，调用后记录状态、Token 和耗时。
一线 Interpreter 仍按现有方式计量；L2 不复用“每条消息只扣一次”的假设。退款审批恢复
本身仍不扣模型额度，只有随后明确进入 `l2_decide` 才产生一次 L2 模型计量。

## 13. 长期记忆 Store

默认位置：

```text
MEMORY_DB_PATH=var/memory.sqlite
```

使用 `SqliteStore.from_conn_string()` 和显式 `setup()`。与业务 migration 分开，首次运行新增：

```bash
python -m commerce_resolve memory setup
```

应用启动只检查 Memory Store Schema 已存在且可读，不隐式创建或重置；缺失时给出上述初始化
命令。每个请求在图执行期间打开 Store，结束后关闭连接。

服务端生成 namespace：

```text
("commerce-resolve", "workspace", workspace_id, "user", user_id, "preferences")
```

浏览器、用户文本和模型不能提供 namespace。key 使用受限 `memory_type`，因此同一用户每类
只有一个当前值。所有读写经 `CustomerPreference` Schema 校验。

写入流程：

```text
模型提出受限偏好
  -> Harness 校验类型、值和用途
  -> 生成 proposal_id 并 interrupt
  -> Web 展示具体内容
  -> 用户 confirm/reject
  -> confirm 后按稳定 key 幂等 put
  -> 重新 get 验证
  -> 记录公开事件
```

用户管理 API 的纠正和删除是明确 R1 操作，使用 Session、CSRF、Origin、当前 namespace 和
进程内 user lock。当前只承诺单 worker；多实例下的 Store CAS 冲突留给后续版本处理。

Checkpoint 删除、Case 删除、业务数据删除和记忆删除互不级联。长期记忆不会自动从历史
对话重新生成，也不会作为订单、政策或退款事实。

## 16. OpenAI-compatible L2 Adapter

`OpenAIL2Agent` 复用通用环境变量：

```text

LLM_MODEL
LLM_BASE_URL
```

但使用独立 Prompt、Schema、timeout 和调用入口，不复用 `OpenAIQueryInterpreter.interpret()`。
配置：

- `response_format={"type":"json_object"}`。
- `stream=False`。
- `max_tokens=800`。
- SDK timeout 为 `15` 秒。
- SDK 自动重试为 `0`；Harness 明确记录失败并决定是否停止。
- 系统 Prompt 只描述决策协议、工具契约和禁止项，不包含业务资格或权限规则。
- SDK/Schema 错误统一映射为 L2 model failure，不把 Provider 细节回传浏览器。

返回 `L2ModelResult(decision, usage)`；若 Provider 不返回 usage，Harness 使用调用前估算值。
不要求模型输出推理过程。

## 18. Checkpoint、恢复与幂等

- Preview、Case、Step、Decision、Tool Call、Memory Proposal 和 Trace Event 都使用稳定 ID。
- `l2_create_case` 使用 `create_case_if_absent`，节点重放返回同一 Case。
- R0 工具读取没有写副作用，但 Trace 通过 event key 幂等。
- Memory 写入使用 `(namespace, memory_type)` 稳定 key；确认重放得到同一值。
- Mock 退款继续使用 v0.4 action/幂等键。
- 每个 `interrupt` 前只写可幂等的 Case/事件；不可幂等副作用放在确认后的独立节点。
- 恢复时重新校验 Session、conversation、Case、Memory proposal 或 Refund action 归属。
- 恢复前检查业务事实和当前预算；旧 Observation 不覆盖最新 R0 工具结果。
- 模型结果若未成功写入 Checkpoint 可以重新获取；每次真实尝试都计入调用和成本预算。

旧 v0.1–v0.4 Checkpoint 不迁移。新增字段全部可选；旧 thread 在下一条消息时正常沿用现有
路径。新增 Pydantic 类型进入显式 serializer 白名单，未知类型继续拒绝恢复。

## 19. 安全与 Prompt Injection

- 用户消息、政策、工具结果和记忆全部作为标记数据传给模型，不能修改系统 Prompt。
- 模型决策必须通过判别联合；未知 `kind`、tool、field 或额外字段立即停止，不猜测修复。
- 工具 Policy 使用服务端 Context 和 Registry，不解析模型自然语言来授权。
- 订单/退款工具每次重新验证当前 BusinessScope；长期记忆不能提供订单号归属证明。
- 搜索查询长度、topic、aspects 和 limit 继续受 v0.2 Schema 限制。
- Memory 值只能是枚举，不保存可执行指令。
- 公开 Trace 对参数和结果做字段白名单与长度限制。
- API Key、Session、CSRF、内部 ID、完整 Prompt 和 Provider 异常不进入 State、Trace 或响应。
- 游客、跨用户、失效 Session、篡改 preview/proposal/action 的调用在模型和工具前被拒绝。

## 26. 风险与缓解

| 风险 | 缓解 |
|---|---|
| Agent 无限循环或成本失控 | 五类预算、重复签名、连续失败和显式停止状态 |
| 模型构造未知工具或参数 | 判别联合、静态 Registry、`extra=forbid`、确定性 Policy |
| Prompt Injection 扩大权限 | 数据边界、服务端 Scope、工具白名单和模型无授权身份 |
| 同步 HTTP 被多次模型调用拖慢 | 每次调用/活跃时长上限；超时安全停止；不隐藏后台任务 |
| Checkpoint 重放重复 Case/Trace/Memory | 稳定 ID、业务唯一约束、event key 和 Store 稳定 key |
| 退款桥接复制或绕过 v0.4 | 只写现有 State 并进入原节点；批准接口、Policy、Gateway 不复制 |
| 长期记忆污染业务事实 | 只允许三类枚举偏好；实时工具和政策始终优先 |
| Store 与业务库无法原子提交 | 记忆写入使用稳定 key、回读验证和公开事件；失败不声明成功 |
| L2 调用重复扣每日额度 | 记录每次真实 Provider 尝试；Case 预算按事件核对，不假装未产生成本 |
| 公开 Trace 泄露敏感内容 | 白名单摘要、长度限制、无 Prompt/CoT/完整工具正文 |
| 主图节点继续膨胀 | L2 模型、Policy、工具、节点、Repository 按职责拆文件，仍保持模块化单体 |
| SQLite 并发限制 | 单 worker、thread/user lock、短事务、唯一约束；不声称生产并发 |

## 27. ADR 判断

本 Plan 不新增 ADR：

- 单个 L2 Harness、AI 披露、记忆和退款审批边界已由 ADR-0006 接受。
- LangGraph、SQLite、服务端访问模式、同源 Web 和 Mock 交易边界已由 ADR-0001 至
  ADR-0005 决定。
- 单图节点模块、JSON 决策、预算数值、表、API 和页面属于 v0.5 可演进实现细节。

如果实施中需要嵌套 Subgraph、多 Agent、向量 Memory、外部客服/工具、异步 Worker、
SSE 协议、真实业务系统或多实例一致性，必须先新增 ADR 和相应 Feature Spec。

## 28. 非目标确认

v0.5 不实现：

- 真人客服、CRM、工单派发、消息、邮件或通知。
- 多 Agent、Supervisor、专家角色或后台自治。
- 任意 SQL、Shell、HTTP、浏览器工具或运行时插件注册。
- 真实订单、物流、支付、退款或外部资金副作用。
- L2 自动批准退款或修改 v0.4 确定性金额/渠道。
- 自由文本长期记忆、静默学习、用户画像或跨用户共享记忆。
- 新向量数据库、Embedding、Rerank 或语义 Memory。
- Token 级网络流式传输、WebSocket、消息队列或生产并发。
- 保存、展示或评估模型隐藏 Chain-of-thought。
