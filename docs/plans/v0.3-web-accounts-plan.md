## 1. Plan 目标

在不复制现有 LangGraph 工作流、不放宽 v0.1/v0.2 安全语义的前提下，为
CommerceResolve 增加一个单实例 Web 产品入口：

- 游客通过浏览器使用共享只读演示数据和 Fake Interpreter。
- 可信操作员签发邀请码，用户注册并建立可撤销的服务端登录会话。
- 注册用户在私有演示工作区管理订单与物流数据。
- 注册用户通过服务端授权的 LLM 查询私有数据和受控政策。
- Web 身份、工作区、模型权限和 thread 归属全部由服务端决定。
- 业务数据库、LangGraph Checkpoint 和政策索引保持物理分离。

本 Plan 只解决 v0.3 已接受的用户结果。退款、Handoff、Agent Loop、公开 API 和
生产多实例部署不进入实现。

## 2. 成功标准

实现完成后必须能够复现以下端到端路径：

```text
游客打开 Web
  -> 服务端创建匿名会话和 thread
  -> 使用 Fake 查询共享 ORD-001
  -> 返回订单/物流或政策结果
  -> LLM 调用为 0

操作员签发邀请码
  -> 用户注册并登录
  -> 自动创建私有工作区
  -> 用户创建订单和物流
  -> LLM 将自然语言解析为结构化查询
  -> Agent 只读取当前私有工作区
  -> 服务重启后继续原 thread
```

同时满足：

- 游客业务写请求无副作用。
- 用户 A 无法读取或修改用户 B 的数据、conversation 或 Checkpoint。
- 客户端无法通过参数选择 LLM、切换身份或工作区。
- 模型失败不会静默回退到 Fake。
- v0.1、v0.2 测试和 Eval 全部继续通过。

## 3. 总体架构

采用模块化单体后端和独立构建的 React SPA。CLI 和 Web API 复用领域模型、Gateway 和
唯一主图：

```text
React SPA
  -> same-origin JSON API
  -> FastAPI routes
  -> Session / CSRF / Access Policy
  -> AccessPrincipal
       actor_id
       user_id | null
       workspace_id
       mode: guest | registered
       llm_allowed
  -> Conversation ownership check
  -> Request-scoped dependency assembly
       guest      -> Fake Interpreter + read-only Demo Gateway
       registered -> quota wrapper + OpenAI Interpreter + SQLite Business Gateway
  -> build_workflow(...)
  -> SQLite Checkpointer
  -> public response

开发：Vite :5173 --/api proxy--> FastAPI :8000
交付：Vite build -> frontend/dist -> FastAPI 同源静态托管

Business SQLite     Checkpoint SQLite     Policy SQLite FTS5
账号/邀请/会话      LangGraph State       可重建政策索引
工作区/订单/物流    conversation thread   不保存账号数据
conversation 归属
```

FastAPI 只负责 HTTP JSON API、SPA 静态资源、认证上下文和依赖装配。LangGraph 不处理
密码、Cookie、邀请码或前端组件；Web 路由也不能直接实现订单查询和政策回答。

## 4. 技术选型

| 领域 | 选择 | 不选择 | 理由 |
|---|---|---|---|
| Web 框架 | FastAPI | Django、Flask | 与 Pydantic 契约兼容，依赖注入和 TestClient 适合当前 Python 项目 |
| Web Server | Uvicorn，单 worker | Gunicorn 多 worker | v0.3 是本地单实例，SQLite 和内存 thread lock 不承诺多 worker |
| 前端 | React + TypeScript | Jinja2 + 原生 JS、Vue | 对话、CRUD 和后续审批/任务状态需要可组合组件；TypeScript 约束 API 数据 |
| 前端构建 | Vite + npm lockfile | Next.js、CDN 脚本 | 不需要 SSR/SEO 或第二个服务端；Vite 只负责开发和静态构建 |
| 前端路由 | React Router | 服务端页面路由 | 登录、注册、chat、订单和物流页面共享同一个 SPA 外壳 |
| 服务端状态 | TanStack Query | Redux、Zustand、自建全局缓存 | 只管理 API 查询、缓存和 mutation 失效；本地 UI 状态继续使用 React Hook |
| 样式 | CSS Modules | Tailwind、MUI、Ant Design | v0.3 页面有限，先避免引入设计系统和额外样式 DSL |
| Chat 传输 | 普通 HTTP 请求/响应 | SSE、WebSocket | 当前图步骤短，v0.3 没有流式验收需求 |
| 业务持久化 | SQLite + SQLAlchemy 2.0 同步 ORM | 原始 `sqlite3`、异步 ORM | 账号与关系数据需要事务和明确映射；现有 Graph/CLI 均同步 |
| Schema 迁移 | Alembic | 启动时 `create_all` | 数据库结构将继续演进，迁移必须显式、可审查、可测试 |
| 密码散列 | `pwdlib[argon2]` | 明文、通用 SHA、旧 Passlib 默认 | Argon2 是当前 FastAPI 官方安全教程推荐算法 |
| 浏览器认证 | 服务端不透明 Session Cookie | JWT、浏览器 localStorage Token | 单体浏览器产品需要撤销、退出和账号停用；不需要无状态跨服务认证 |
| CSRF | 服务端同步 Token + Origin 校验 | 只依赖 SameSite | Cookie 会自动随请求发送，所有写请求需要显式用户来源证明 |
| LLM | 现有 OpenAI-compatible Chat Adapter | 浏览器直连模型 | API Key 和模型权限必须留在服务端 |
| Agent | 现有唯一 LangGraph 主图 | Web 专用 Graph、第二个 Agent | 避免 CLI 与 Web 的业务、安全语义漂移 |
| 测试 | pytest/TestClient + Vitest/Testing Library + Playwright | 真实模型作为 CI 门禁 | API、安全边界、组件交互和关键浏览器路径均可离线验证 |

### 4.1 为什么不选择 JWT

v0.3 只有同源浏览器客户端和单体服务，没有跨服务、移动端或第三方 API。服务端
Session 可以立即撤销、退出、停用账号并绑定 CSRF；JWT 会增加签名密钥、刷新、吊销和
浏览器存储决策，却不产生当前用户价值。

### 4.2 为什么选择最小 React SPA

如果 v0.3 是一次性演示，Jinja2 + 原生 JavaScript 的实现成本更低。但长期路线还包含
退款审批、任务暂停/恢复、Handoff、Agent Loop 状态和 Eval 结果展示；继续累积页面脚本
会在后续版本产生整体迁移成本。React 负责可组合 UI，TypeScript 负责浏览器侧契约，
TanStack Query 只负责服务端状态，不引入 Redux/Zustand。

这项选择不放宽 Spec 中“复杂前端状态框架”的非目标：v0.3 不实现流式 Chat、乐观资金
操作、离线缓存或复杂全局状态。前端仍是同源客户端，身份、工作区、模型权限和业务规则
全部由 FastAPI 决定。

### 4.3 为什么不选择 Next.js

当前产品不依赖 SEO、服务端 React 渲染或边缘运行；FastAPI 已经承担认证、业务 API 和
Agent Runtime。Next.js 会增加第二个服务端、Session 转发和部署边界，却不能改善 v0.3
的身份隔离或 Agent 结果。Vite 构建静态 SPA 后由 FastAPI 同源托管即可。

### 4.4 为什么使用同步 SQLAlchemy

现有 OpenAI Adapter、LangGraph 节点、SQLite Policy Repository 和 Checkpointer 均为
同步实现。v0.3 单实例负载不需要异步数据库；同步路由和短事务更容易测试事务边界。
如果后续性能数据证明数据库等待成为瓶颈，再通过 ADR 评估 AsyncSession/PostgreSQL。

### 4.5 依赖管理

实现时向直接依赖增加稳定版本线：

```text
fastapi
uvicorn
sqlalchemy 2.0.x
alembic 1.x
pwdlib[argon2]
```

开发依赖增加 `httpx`，供 FastAPI/Starlette TestClient 使用。OpenAI SDK 继续保留为
`openai` 可选依赖；游客、离线测试和管理命令不要求安装或调用真实模型。

前端直接依赖保持最小集合：

```text
react
react-dom
react-router-dom
@tanstack/react-query
```

开发依赖使用 TypeScript、Vite、React Vite Plugin、Vitest、Testing Library、
Playwright 和 `openapi-typescript`。使用 npm 与提交到 Git 的 `package-lock.json`；不同时
维护 npm、pnpm 和 yarn lockfile。

本 Plan 不写死尚未安装的 Patch 版本。T1/T2 实施时分别根据 Python 3.12 和本机 Node
运行时选择稳定兼容版，写入 `requirements.lock` 与 `frontend/package-lock.json`，并通过
完整回归后冻结。不得采用 beta/rc。

## 7. 业务数据库设计

`business.sqlite` 是业务事实和 Web 权限来源，不与 Checkpointer 或 RAG 索引共库。

### 7.1 表结构

#### users

```text
id                  UUID/稳定字符串，主键
username_normalized 唯一、小写规范化账号
password_hash       Argon2 Hash
status              active | disabled
created_at
```

首版用户名限制为 3–32 个 ASCII 字母、数字、点、下划线或连字符；统一转小写。
密码接受 12–128 个 Unicode 字符，不设置容易误导的字符种类组合规则。

#### workspaces

```text
id
owner_user_id       users.id 唯一外键
created_at
```

一个注册用户只拥有一个私有工作区。游客使用代码中定义的共享 `demo` 工作区，不在
`workspaces` 中创建可写记录。

#### invitations

```text
id
code_hash           高熵邀请码摘要，唯一
expires_at
max_uses
used_count
revoked_at | null
created_at
```

邀请码使用 `secrets` 生成至少 32 字节随机值，只在创建时向操作员显示一次；数据库只
保存摘要。注册事务必须原子完成“校验与占用邀请码、创建 user、创建 workspace”。

默认 `max_uses=1`、七天过期；CLI 可以收紧或调整，不能创建无限有效邀请码。

#### web_sessions

```text
id
token_hash          不透明 Cookie Token 的摘要，唯一
actor_type          guest | registered
subject_id          guest UUID 或 user ID
user_id | null
csrf_token_hash
created_at
expires_at
revoked_at | null
```

- 浏览器只持有随机 Session Token；数据库不保存原始 Token。
- 登录成功后销毁 pre-session 并生成新 Session，防止 Session Fixation。
- 退出、账号停用和过期会话必须拒绝访问。
- 每次请求不滑动延长有效期；v0.3 不实现 Refresh Token。

#### conversations

```text
thread_id           随机 UUID，主键
subject_id          与 Session/账号身份绑定
workspace_id        demo 或私有 workspace ID
access_mode         guest | registered
created_at
updated_at
```

此表只保存 thread 归属，不复制 LangGraph 消息。请求携带 thread ID 时，必须先按当前
Principal 查询 `conversations`；未授权和不存在使用统一错误。

#### orders

```text
id                  内部主键
workspace_id
order_id            用户可见标识
user_id             当前工作区拥有者
status              processing | shipped | delivered | cancelled
created_at
updated_at
UNIQUE(workspace_id, order_id)
```

不提前增加退款金额、支付渠道、商品明细等 v0.4 字段；后续通过迁移增加。

#### shipments

```text
id
workspace_id
order_pk            orders.id 外键，v0.3 一单一条物流
status              preparing | in_transit | delivered
last_event
estimated_delivery_at | null
created_at
updated_at
UNIQUE(order_pk)
```

外键和 Repository 必须同时验证 shipment 与 order 位于同一 workspace。删除订单时在
单个事务中删除物流后删除订单；页面必须二次确认，但它不是 Agent 工具。

#### llm_daily_usage

```text
user_id
usage_date           UTC 日期
accepted_calls
PRIMARY KEY(user_id, usage_date)
```

配额检查和计数在调用模型前使用单个事务完成；一旦服务端接受调用即计数，因为上游失败
也可能已经产生费用。游客不进入此表。

### 7.2 SQLite 配置

- 强制 `PRAGMA foreign_keys=ON`。
- 设置有限 `busy_timeout`，避免锁竞争立即转成内部异常。
- 使用 WAL 提高单实例读写并发，但不宣称支持多实例。
- 所有事务保持短小；模型和 LangGraph 调用不能发生在业务数据库事务内。
- SQLAlchemy Engine 和 Session 由应用工厂管理，请求结束必须关闭 Session。
- 测试使用独立临时文件，不使用进程共享内存库掩盖重启问题。

## 8. Schema 迁移

- 使用 SQLAlchemy 2.0 Declarative 映射表结构。
- Alembic 迁移文件提交 Git，业务数据库本身不提交。
- T1/T2 的初始迁移只创建当前任务需要的表；后续任务通过新 revision 增量增加。
- 应用启动只检查当前 revision 是否为 head；不自动升级或 `create_all`。
- 本地升级命令：

```bash
python -m commerce_resolve db upgrade
```

- 集成测试必须覆盖空库升级到 head，以及落后 revision 时服务拒绝启动并给出脱敏提示。
- v0.3 仍处于开发期，不迁移现有 Fake 订单；注册工作区从空数据开始。

## 9. 身份、Session 与 CSRF

### 9.1 AccessPrincipal

Web 认证层输出不可由用户直接构造的 `AccessPrincipal`：

```text
actor_id       guest session subject 或 user ID
user_id        注册用户 ID；游客为 null
workspace_id   demo 或私有 workspace
mode           guest | registered
llm_allowed    服务端 Policy 计算结果
```

`workspace_id`、`mode` 和 `llm_allowed` 不进入表单或 chat JSON 的可写 Schema。即使浏览器
提交同名字段，Pydantic 也必须以 `extra="forbid"` 拒绝。

### 9.2 Session Cookie

- 使用至少 32 字节 CSPRNG 不透明 Token，Cookie 中不编码账号或权限。
- Cookie 属性：`HttpOnly`、`SameSite=Lax`、`Path=/`、不设置 `Domain`；HTTPS 时
  `Secure=true`。
- 不把 Session Token 放入 URL、HTML、JavaScript、localStorage 或日志。
- 数据库只保存 Token Hash；比较和失效由 Auth Repository 完成。
- 认证失败执行一次 dummy Argon2 验证，减小账号枚举的时序差异。

### 9.3 CSRF

- 每个 pre-session/Session 生成独立 CSRF Token，数据库保存摘要。
- React 启动时通过同源 Session API 取得 CSRF Token，只保存在当前页面内存中，不写入
  localStorage；所有 mutation 使用 `X-CSRF-Token` Header。
- 所有 POST/PUT/PATCH/DELETE 先验证 Session、CSRF 和 Origin，再执行业务逻辑。
- GET/HEAD/OPTIONS 不产生状态变化。
- 登录成功后销毁 pre-session 并同时轮换 Session 与 CSRF Token。
- SameSite 和 Origin 只是纵深防御，不能代替 CSRF Token。

## 10. 邀请和账号流程

可信本地操作员使用：

```bash
python -m commerce_resolve invite create \
  --expires-in-hours 168 \
  --max-uses 1

python -m commerce_resolve invite revoke --invite-id <id>
```

注册事务：

```text
接收 username + password + invitation code
  -> 规范化并校验账号
  -> 计算邀请码摘要
  -> 开启 IMMEDIATE/等价写事务
  -> 校验未过期、未撤销、used_count < max_uses
  -> 校验 username 不存在
  -> 创建 user 和 workspace
  -> used_count + 1
  -> 提交
  -> 不自动登录，跳转登录页
```

注册失败使用有限公开错误：邀请码不可用、账号格式无效、账号已不可用；不回显邀请码、
Hash 或数据库原因。重复并发注册不能超额消费邀请码。

## 11. SPA 路由与内部 JSON API

v0.3 不承诺公开 API。React Router 管理以下浏览器路径；FastAPI 在生产构建中对这些路径
返回同一个 `index.html`，具体身份和数据始终通过 `/api` 查询：

| 浏览器路径 | 访问 | 结果 |
|---|---|---|
| `/`、`/chat` | 所有 | 对话入口和当前访问模式 |
| `/register` | 游客 | 邀请注册页 |
| `/login` | 游客 | 登录页 |
| `/orders` | 注册用户 | 私有订单与物流管理 |

同源内部 JSON API：

| 方法与路径 | 访问 | 结果 |
|---|---|---|
| `GET /api/session` | 所有 | 返回公开身份模式、CSRF Token 和能力，不返回 Session Token |
| `POST /api/conversations` | 所有 | 为当前 Principal 创建随机 thread |
| `POST /api/chat/messages` | 所有 | 验证 thread 归属并执行一轮 Graph |
| `POST /api/auth/register` | 游客 | 消费邀请码并创建账号/工作区 |
| `POST /api/auth/login` | 游客 | 轮换 Session 并登录 |
| `POST /api/auth/logout` | 注册用户 | 撤销 Session 并返回游客模式 |
| `GET /api/orders` | 注册用户 | 列出私有订单与物流 |
| `POST /api/orders` | 注册用户 | 创建订单及可选物流 |
| `PATCH /api/orders/{order_id}` | 注册用户 | 更新当前工作区数据 |
| `DELETE /api/orders/{order_id}` | 注册用户 | 确认后删除当前工作区数据 |

开发环境由 Vite 将 `/api` 代理到 FastAPI，因此浏览器仍以同源方式发送 Cookie，不配置
credentialed CORS。生产环境由 FastAPI 托管 `frontend/dist`，API 与 SPA 保持同源。

### 11.1 Chat 请求和响应

浏览器 Chat API 只提交：

```text
thread_id
message
```

服务端忽略/拒绝额外字段，不接受 `user_id`、`workspace_id` 或 Interpreter。响应只包含：

```text
thread_id
assistant_message
public_status
citations[]
```

React 只把模型与工具输出作为字符串渲染，不使用 `dangerouslySetInnerHTML`。静态资源全部
进入 Vite 生产构建，不使用 CDN。FastAPI OpenAPI Schema 通过 `openapi-typescript` 生成
TypeScript 类型；生成结果只负责类型同步，不替代运行时 Pydantic 校验或服务端授权。

## 12. LangGraph 与 Gateway 集成

### 12.1 唯一主图

Web 继续调用 `build_workflow()`，不创建 Web 专用 StateGraph。每个请求按 Principal 装配
依赖并编译短生命周期 Graph，Checkpointer 使用短生命周期 SQLite 连接；这样不在全局
Graph 中保存用户、数据库 Session 或模型配额状态。

单实例内对相同 thread 使用进程内锁拒绝并发执行；第二个同时请求返回 `409`。v0.3 不
承诺多 worker，因此该锁不作为未来分布式互斥方案。

### 12.2 RunContext 和 State 兼容

`RunContext` 增加：

```text
workspace_id
access_mode: cli | guest | registered
```

保留现有 `user_id`，其值来自可信 Principal。`AgentState` 增加可选
`owner_workspace_id`。`bind_and_interpret` 必须同时验证已有 owner user 和 workspace，
不匹配时在进入 Interpreter/业务工具前终止。

旧 Checkpoint 没有 `owner_workspace_id`，采用兼容绑定策略：

- CLI 使用稳定的 `cli-demo` workspace。
- 首次恢复旧 State 时，如果 owner user 匹配且 workspace 字段缺失，补写当前可信
  `cli-demo`；存在且不匹配则拒绝。
- 不重命名或删除 `owner_user_id`，因此不需要批量迁移已有开发期 SQLite。

### 12.3 Gateway 作用域

订单和物流 Gateway 必须同时接收可信用户/工作区作用域。尤其要修正当前
`LogisticsGateway.get_shipment(order_id)` 只依赖先前订单鉴权的隐式假设，使同一订单号
可以安全存在于不同私有工作区。

推荐契约语义：

```text
OrderGateway.get_order(scope, order_id)
LogisticsGateway.get_shipment(scope, order_id)
```

`scope` 只包含服务端生成的 `user_id`、`workspace_id` 和 access mode。Fake 与 SQLite
实现共享该契约；Repository 使用 `(workspace_id, order_id)` 查询，并验证 user 归属。

### 12.4 游客依赖

- Fake Interpreter 使用现有受控规则。
- Demo Order/Logistics Gateway 读取代码内预置数据，忽略任何客户端身份字段。
- Guest Gateway 没有创建、更新或删除方法。
- 每个游客使用独立 `actor_id`/thread，但共享的数据只包含明确公开的 demo 记录。
- Policy Repository 继续使用当前只读 FTS5 索引。

### 12.5 注册用户依赖

- `QuotaEnforcedInterpreter` 在模型调用前以 user ID 原子检查并计量配额。
- 内部委托现有 `OpenAIQueryInterpreter`，输出仍由 Pydantic 校验。
- SQLite Business Gateway 按可信 scope 查询私有订单和物流。
- Policy Repository 与游客共享只读政策来源，不复制索引。
- 模型未配置、未授权、配额不足和上游失败映射为不同公开错误码，但不回退 Fake。

## 13. Conversation 与 Checkpoint 归属

创建 conversation 时，业务库记录 thread 与 Principal 的绑定；随后才允许首次 Graph
调用。调用顺序：

```text
解析 Session
  -> 得到 Principal
  -> 查询 conversation(subject_id, workspace_id, mode, thread_id)
  -> 归属不匹配则统一 404/不可访问
  -> 打开 Checkpointer
  -> 以相同 thread_id invoke
  -> 关闭 Checkpointer
```

- 不通过“先读取 Checkpoint 再检查 owner”完成授权，避免在授权前接触其他用户 State。
- 注册用户的 conversation 不随登录 Session 退出而删除；重新登录后可继续。
- 游客 conversation 绑定 guest subject；Session 过期后不提供恢复入口，并可由维护命令清理。
- 删除 conversation 和删除 Checkpoint 暂不作为 v0.3 用户功能；只记录后续数据生命周期需求。

## 14. LLM 权限与成本边界

LLM 访问由服务端 `LlmAccessPolicy` 决定：

```text
registered
AND user.status == active
AND LLM 配置完整
AND daily_usage < configured_limit
AND feature not administratively disabled
```

- 游客在装配阶段就没有 OpenAI Interpreter，不能仅靠路由判断阻止调用。
- 计量记录模型调用尝试次数，不在 v0.3 精确统计 Token 费用。
- 默认每个注册用户每 UTC 日 20 次，环境变量只能由服务端操作员修改。
- 配额拒绝发生在模型调用前；模型上游失败仍计入已接受调用。
- 自动化测试注入 Spy Interpreter，断言游客调用次数为 0、注册路径参数正确。
- 真实 DeepSeek 冒烟只使用受邀测试账号和临时工作区，不写入 Eval 门禁。

## 15. 安全响应与日志

- 认证、邀请和跨工作区访问错误不记录密码、原始 Session Token、完整邀请码或 Cookie。
- 应用日志只记录 request ID、actor 类型、脱敏 user/workspace ID、route、status、耗时和
  公开错误码。
- Chat Audit 继续记录稳定节点和工具步骤，不记录完整 Prompt 或政策正文。
- Web 层设置最小安全 Header：`X-Content-Type-Options: nosniff`、禁止 framing、合理的
  `Referrer-Policy` 和仅允许本地资源的 CSP。
- 不配置跨域凭证 CORS；v0.3 只允许同源浏览器。
- 表单长度、chat 消息长度和分页大小使用 Pydantic/服务端约束，拒绝超长输入。
- 注册、登录和 chat 至少提供单实例内的简单限流；精确分布式限流留到生产版本。

## 21. 风险与缓解

| 风险 | 缓解 |
|---|---|
| Web 身份字段被客户端伪造 | 唯一来源为 Session-derived Principal；请求 Schema 禁止额外权限字段 |
| 跨用户 thread 泄露 | 业务库先校验 conversation 归属，再读取 Checkpoint |
| 邀请并发超额消费 | 邀请占用、用户和 workspace 创建放在同一写事务 |
| Session 被窃取 | 高熵不透明 Token、DB 仅存 Hash、HttpOnly/Secure/SameSite、过期和撤销 |
| CSRF 修改业务数据 | 同步 CSRF Token、Origin、无 GET 写操作、Session 轮换 |
| XSS 读取数据或发请求 | React 字符串转义、禁止 raw HTML、本地构建资源、CSP |
| 游客绕过模型限制 | 游客依赖图中根本不装配 LLM；Spy 测试和 Eval 断言 0 调用 |
| LLM 成本失控 | 注册限定、日配额、调用前原子计数、单实例限流 |
| SQLite 锁竞争 | 同步短事务、WAL、busy timeout、单 worker、同 thread 并发拒绝 |
| Graph State 返回旧业务事实 | State 不持久化业务正文作为下一轮事实；每轮重新查询 Repository |
| Gateway 只按订单号查询物流 | v0.3 显式加入可信 user/workspace scope |
| Web 和 CLI 业务行为漂移 | 复用唯一 Graph/Gateway；Web 只负责 Principal 与依赖装配 |
| 前后端 API 类型漂移 | FastAPI OpenAPI 生成 TypeScript 类型；CI 执行生成检查和 typecheck |
| 前端构建链增加维护成本 | 只使用 npm 单一 lockfile；FastAPI 交付一个静态 `dist`；CI 验证 build |
| 技术栈过重 | SPA 只采用 React/Router/Query；不引入 Next.js、Redux、设计系统、WebSocket 或多 Agent |
