# Technical Plan：v2.0.1 意图澄清循环

状态：Completed

对应 Spec：
[`../specs/v2.0.1-intent-clarification.md`](../specs/v2.0.1-intent-clarification.md)

## 目标

在不改变既有业务工具、退款审批和 L2 中断协议的前提下，让 `unknown` 成为可恢复的正常图状态，
通过 LangGraph Checkpoint 控制最多两轮澄清并提供确定性兜底。

## 技术方案

### State 与解释上下文

- `AgentState.intent_clarification_attempts` 保存已经发出的澄清问题数。
- `AgentState.status` 增加 `awaiting_intent_clarification` 和 `intent_unresolved`。
- `InterpretationContext.pending_intent_clarification` 告诉解释器当前文本是在回答澄清问题。
- 识别成功或达到上限后把计数重置为 `0`。

### 图节点与路由

- `bind_and_interpret` 接受 `unknown`，不再抛出 `ValueError`。
- `route_after_interpret` 根据当前次数路由到：
  - `clarify_intent`：输出第 1 或第 2 轮问题并增加次数。
  - `respond_intent_fallback`：第三次仍未知时输出兜底并清空次数。
- 两个节点均连接 `END`；下一条用户消息从 `START` 再次进入解释节点。

### 解释器

- OpenAI-compatible Prompt 明确区分未知、模糊动作和已识别但不支持的动作。
- `pending_intent_clarification` 只辅助理解当前短回复，不能授权工具。
- 对“退库”等退款/退货歧义词做确定性安全拦截并返回 `unknown`。

### 公开运行

- Conversation Projection 复用现有文本消息和字符串 `public_status`。
- Runtime 增加澄清阶段事件，不新增前端协议或数据库迁移。
- 能力边界文案同步反映当前已经支持经审批的 Mock 退款。
