# v1.3.1 商业产品可信度评审量表

状态：Accepted  
日期：2026-07-24

本量表用于补充功能测试。评分只针对固定演示工作区和
[`v1.3.1-screenshot-manifest.md`](v1.3.1-screenshot-manifest.md) 中的页面，不替代权限、
数据一致性、Agent 或安全测试。

## 评分规则

- 每一维只允许 `1`、`2`、`3` 分。
- 发现任一阻塞任务的缺陷，该维最多 `2` 分。
- 没有固定截图或可重复数据，该维不得评为 `3` 分。
- 八个维度全部达到 `3` 分，才满足 v1.3.1 产品评审门禁。

## 八维锚点

| 维度 | 1 分 | 2 分 | 3 分 |
|---|---|---|---|
| 信息架构 | 页面按技术模块堆叠，主任务不明确 | 主任务存在，但入口、上下文或下一步需要寻找 | 首屏即可识别当前事实、主要任务和下一步，客户与运营职责清晰分离 |
| 内容完整性 | 大面积空白、占位资源或单条数据 | 核心路径有内容，但异常、历史或组合场景不足 | 固定工作区覆盖订单、物流、服务、审批、会话和运营状态，数据彼此一致 |
| 视觉层级 | 大标题、装饰或卡片同权抢占注意力 | 基本层级可读，但主次、密度或留白不稳定 | 页面标题克制，事实与动作优先，密度适合对应角色，扫读路径稳定 |
| 业务可信度 | 出现测试 SKU、破图、研发错误或矛盾金额 | 主要事实正确，但文案或边界重复暴露 Demo 感 | 商品、金额、履约、服务和动作一致；演示边界克制且始终可发现 |
| 任务连续性 | 切页、刷新或恢复后丢失上下文 | 数据可恢复，但用户需要重新定位或理解状态 | 首页、订单、服务和助手共享上下文，刷新、登录和恢复后继续同一任务 |
| 状态与反馈 | Loading/Error/Pending 使用技术异常或只靠颜色 | 状态可理解，但缺少下一步或部分页面不一致 | 加载、空、失败、审批、完成和过期都有统一业务语言、图形/文字和恢复动作 |
| 响应式与可访问性 | 核心动作溢出、遮挡或键盘不可达 | 三视口可用，但阅读顺序、焦点或触控密度不稳定 | 三视口主任务可发现；键盘、焦点、Alt、颜色非唯一和 Reduced Motion 均有证据 |
| 开源与面试证据 | 只能靠作者演示，代码与文档无法定位 | 有 README 和测试，但设计取舍或失败边界不完整 | Spec、Plan、ADR、代码指南、Eval、截图和已知限制可独立解释技术与产品决策 |
