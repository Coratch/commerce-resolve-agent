# Agent 能力地图与项目差距分析

日期：2026-07-26。

本文档以 2025–2026 国内 AI Agent 开发岗位 JD 调研（字节、腾讯混元、美团、阿里云、小红书、
百度、DeepSeek、月之暗面等 14 条已验证 JD 与 200+ JD 汇总分析）为输入，整理出 Agent 开发
工程师能力地图（L0–L7），并对照 CommerceResolve 当前实现（v2.0.1）逐项标注覆盖状况，
输出缺口清单与补齐优先级，用于指导 v2.1 及后续版本规划与面试准备。

标注：✅ 已有扎实证据｜⚠️ 部分覆盖｜❌ 未覆盖。

## 能力地图分层原则

每层回答一个互斥的问题，从模型到产品逐层递进：

```text
L0 怎么和模型对话 → L1 知识从哪来 → L2 怎么行动 → L3 记住什么、每次带什么
→ L4 怎么知道好坏 → L5 怎么不出事 → L6 怎么交付上线；L7 为扩展方向
```

## 逐层覆盖状况

### L0 模型交互基础

| 能力 | 状态 | 说明 |
|---|---|---|
| Prompt Engineering | ✅ | 结构化解释 Prompt；变更被固定 Eval 回归覆盖 |
| 结构化输出 | ✅ | JSON mode + Pydantic 严格校验；资格评测结构化有效率 100% |
| 原生 Function Calling 协议 | ❌ | 适配器为 `response_format=json_object`，未走 `tools`/`tool_calls` |
| 流式输出 | ⚠️ | SSE 步骤级事件 + Last-Event-ID 重放已有；模型调用 `stream=False`，无 token 级流式 |
| 多模型适配 | ⚠️ | OpenAI-compatible 单 Provider；"失败不降级"为显式策略，无路由/降级链 |

## 缺口清单

完全缺失：

1. 原生 Function Calling 协议（L0）
2. Token 级流式输出（L0）
3. Embedding / 向量检索、混合召回、Rerank（L1）
4. 多格式解析与多模态检索（L1）
5. 通用 Chunking 策略（L1）
6. MCP / A2A 协议（L2）
7. 显式任务规划与 Reflection（L2）
8. 多智能体协作（L2）
9. LLM-as-Judge 评审（L4）
10. 行业可观测工具对齐（L4）
11. 成本优化手段（L6）

部分缺失：

1. Docker 参考环境验收（L6，实现已有、验收延后）
2. 多模型路由/降级链（L0，"失败不降级"为有意边界）
3. 多智能体分层叙事的论证 ADR（L2）

## 补齐优先级

| 优先级 | 事项 | 理由 |
|---|---|---|
| P0 | 向量/混合检索 + Rerank + FTS5 基线对比 Eval | JD 频次最高的成块缺口；v2.1 路线已排；可复用既有检索评测基建量化收益 |
| P0 | MCP 最小接入（R0 只读工具暴露为 MCP Server） | 2026 年 JD 上升最快关键词；与固定 Tool Registry 叙事衔接；权限链路不变 |
| P0 | Langfuse / OpenTelemetry 导出通道 | Tracing 实质已完成，仅缺行业词汇对齐；工作量小 |
| P1 | 原生 Function Calling 对照路径 | 与 JSON mode 的取舍是高频面试点 |
| P1 | Token 级流式输出 | 感知延迟优化；与既有步骤级 SSE 形成分层流式 |
| P1 | 规划/反思节点，或"为什么单步决策"ADR | 补范式覆盖或补论证 |
| P1 | LLM-as-Judge 与规则断言一致性实验 | 评测方法论加分项 |
| P1 | Docker 参考门禁补跑 | 销掉延后的交付验收 |
| P2 | 模型路由、语义缓存、记忆衰减策略 | 可选加分 |
| 放弃 | 微调、Computer Use、高并发分布式 | 应用岗非核心；面试讲清取舍即可 |

## 面试主打区

以下能力 JD 稀缺且本项目有量化证据，应作为面试主动展开的重点：

- L4 评测工程化：四层门禁、Baseline 回归、故障注入、真实 Provider 资格评测。
- L5 安全边界：LLM 与资金权限分离、注入防护、安全违规 0 的发布门禁。
- L3 上下文工程：Context Pack/Manifest、预算硬限制、长上下文削减 77.8%。
- L2 可靠性：`interrupt` 审批与重校验、幂等执行、回读验证、失败归因。
